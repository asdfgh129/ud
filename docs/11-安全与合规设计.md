# 11 安全与合规设计

> 文档编号：UD-DOC-11 ｜ 版本：v0.3 ｜ 状态：草案（P0 控制已落地，仍需安全/法务评审） ｜ 日期：2026-11-09

> **v0.3 说明**：`make gates` 已把 CycloneDX SBOM、许可证扫描、`govulncheck` 纳入可复跑门禁并接入 CI；首次扫描发现真实漏洞 `GO-2026-6809`（Go 1.27.2 `crypto/x509`），已通过把工具链升到 1.27.3 修复并复扫干净。§10 残余风险第 4 条据此更新。
>
> **v0.2 说明**：§1–§4 中适用于 HTTP(S) 直链的控制已在 P0 实现，§5–§9 中涉及插件 / sidecar / P2P / 平台的条款尚无对应代码（P1+）。P0 的实际覆盖面与残余风险集中登记在 §10，避免把「规范已写」误读为「能力已具备」。

## 1. 安全目标与信任边界

**信任边界**：核心 Go 进程内为可信域；以下全部为**不可信输入**——用户提交的 URL / 种子 / Metalink / m3u8 / MPD、站点返回的 HTML 与流地址、插件脚本、重定向链、tracker 返回的 peer 列表、sidecar 输出 JSON。

| STRIDE | 主要威胁 | 控制 |
|---|---|---|
| Spoofing | 伪造 tracker / 镜像、DNS 重绑定 | TLS 校验、SSRF Guard、哈希校验 |
| Tampering | 分片被篡改、恶意 Metalink piece hash | 整文件 + 分块校验、`.part` 原子提交 |
| Repudiation | 任务来源与凭据使用不可追溯 | 脱敏审计事件（`events` 表） |
| Information Disclosure | Cookie/passkey/session 泄漏、日志脱敏失败 | 钥匙串、按任务最小化传递、`security.Redact` |
| DoS | 超大 XML、镜像爆炸、zip bomb、插件死循环 | 大小/数量/超时/内存上限、并发信号量 |
| Elevation | 插件调用 subprocess、提权助手被滥用 | 能力裁剪、WASM 隔离、独立授权 |

## 2. SSRF 防护规范（最高优先级）

Resolver 是本项目最大攻击面。所有由不可信输入产出的 URL（含 Metalink 镜像、m3u8 分片、站点重定向、yt-dlp `formats[].url`）必须经 `security.SSRFGuard`：

| 规则 | 要求 |
|---|---|
| 协议白名单 | 只允许 `http / https / ftp / ftps / sftp`；禁用 `file://`、`gopher://`、`dict://` 等 |
| 地址校验 | **解析后校验 IP**，拒绝回环、私网、链路本地（`169.254.0.0/16`，含云元数据）、组播、保留段、IPv4-mapped IPv6 私网 |
| DNS 重绑定 | 一次解析、Pin 住已校验 IP 用于实际连接；禁止二次解析 |
| 重定向 | **逐跳校验**，最多 3 跳；跨 host 重定向重新走完整校验 |
| 端口 | 默认仅 80/443/21/22/990 等；非标端口需用户显式允许 |
| 数量与大小 | Metalink 镜像 ≤ 32、XML ≤ 4MiB、禁止 DTD/外部实体；m3u8 分片数上限 |
| 凭据 | 重定向到不同 host 时**剥离** Authorization/Cookie，防止凭据外泄 |
| 失败 | 返回 `E_RESOLVE_SSRF_BLOCKED` 并记审计事件，不重试 |

## 3. 凭据管理

| 数据 | 存放 | 规则 |
|---|---|---|
| Cookie / Authorization / 代理密码 | 系统钥匙串 | SQLite 只存 `credential_ref`；按任务最小集合传递；任务结束释放 |
| PT passkey | 钥匙串 | **不进日志、不进事件、不跨任务同步**；announce URL 在内存中拼接 |
| Telegram session | 文件 0600 | 加密存储；`FLOOD_WAIT` 与会话失效需重新授权流程 |
| eD2k RSA 身份 | 文件 0600 | 必须持久化，否则重启换身份、积分归零 |
| Sidecar | — | 不继承核心环境变量；不共享全局凭据；工作目录限于下载目录 |

日志、事件、错误详情、`/tasks` 响应统一经过 `security.Redact`；PR 评审清单包含「新增日志字段是否可能含敏感值」。

## 4. 文件系统安全

- `ResourceFile.Path` 必须经 `PathGuard`：拒绝绝对路径、`..` 穿越、符号链接逃逸、Windows 保留名、超长路径。
- 输出统一写 `<target>.part`，校验通过后核心原子 `rename`；临时文件权限 0600。
- 磁盘预检：所需空间 ≥ 输入 + 输出（后处理约 2×）；空间不足返回 `E_STORAGE_FULL` 而非 OOM。
- 删除任务带 `withFiles` 时限定在任务输出目录内，禁止递归到任意路径。
- `thunder://` 解码结果必须重新校验 scheme 与 URL 合法性，禁止直接拼接执行。

## 5. 插件与 sidecar 隔离

- goja 插件默认无 `fs` / `env` / `subprocess`；网络只能走宿主注入的白名单 `ctx.http`（详见 `08`）。
- 第三方规则包必须 Ed25519 签名校验；需要硬隔离时用 wazero/Extism 裁剪 WASI 能力。
- sidecar 通信走 stdin/stdout JSON-RPC，不占端口、无网络鉴权面；超时强杀；崩溃自动重启上限 3 次。
- **插件/sidecar 不得自行下载或写最终文件**；yt-dlp 只吐 JSON，ffmpeg 只读本地文件。
- 提权助手独立进程、单独分发、默认不安装，每次提权操作需显式用户授权。

## 6. 许可证合规

| 组件 | 义务 | 落地动作 |
|---|---|---|
| MIT / ISC / BSD / Unlicense | 保留版权与 LICENSE | 打包 `THIRD_PARTY_NOTICES` |
| MPL-2.0（`anacrolix/torrent`） | 修改文件需以 MPL 提供 | 记录 fork/补丁清单，随发布提供 |
| **LGPL-2.1+（ffmpeg）** | 不带 gpl/nonfree；动态链接或**不链接**；随附精确对应源码与 configure 行；About/EULA 声明；EULA 不得禁止逆向 | **exec 独立 CLI 为最优形态**；锁定 LGPL 构建、保留 `buildconf`、随包提供源码获取方式 |
| GPL-2.0 | 高分发义务 | **传输路径已清零**；BYO 适配器若接入须独立进程 arm's-length + 法务确认 |
| `--enable-nonfree` | 二进制不可再分发 | 禁止使用（如 `ffmpeg-static` darwin-arm64） |

生成 SBOM（CycloneDX）+ `go version -m` 校验，作为发布门禁（`13`）。

## 7. 平台条款与法律边界（必须写进产品）

| 项 | 立场 |
|---|---|
| **私有 tracker** | 不承诺准入；保持诚实 PeerID，**禁止伪装** qBittorrent/Transmission 白名单身份；需要 PT 时做 BYO 适配器把任务交给用户已安装的白名单客户端（qBittorrent WebUI） |
| **迅雷 P2SP** | 私有协议，仅做链接解码；产品不得出现「迅雷加速」「高速通道」「离线下载」 |
| **DRM** | 明确不碰 Widevine / FairPlay / PlayReady；不提供规避技术措施的能力 |
| **视频站 / yt-dlp** | 能力限定为「下载用户有权保存的内容」；遵守站点 ToS 与 robots；不提供会员内容绕过；不内置账号共享 |
| **微信视频号** | 涉及逆向、MITM CA、JS 注入与平台条款；作为单独分发、默认不安装的可选插件，权限与风险与主程序物理隔离 |
| **Telegram** | 遵守 MTProto 与平台限速；`FLOOD_WAIT` 必须退避，不做规避限速的多账号滥用 |
| **eD2k / BT** | 明确做种义务与反吸血礼仪；不做 PeerID 伪装、不做假进度 |
| **App Store / Play** | iOS 不得派生子进程或下载可执行代码；Android 不得 exec 应用私有目录文件；按需下载 sidecar 仅在桌面启用 |

## 8. 隐私

- 遥测**默认关闭**，需用户显式同意；只上报能力错误码与版本号，不上报 URL、文件名、凭据。
- 日志与事件保留期可配（默认 7 天）；`udctl backup` 导出不含凭据明文。
- 崩溃报告上传前经脱敏与用户确认。

## 9. 安全测试与响应

- `12` 的 SSRF 用例集、恶意 Metalink / m3u8 用例集、路径穿越用例集作为发布门禁。
- 依赖漏洞扫描（`govulncheck` + SBOM）纳入 CI；高危漏洞 7 天内修复或降级能力。
- 安全事件流程：发现 → 定级 → 修复/缓解 → 发布通告 → 复盘并更新本文档与 ADR。

## 10. P0 安全实现基线与残余风险

| 本文条款 | P0 实现 | 测试 |
|---|---|---|
| §2 协议/端口白名单、解析后 IP 校验（含 IPv4-mapped IPv6）、DNS pin、逐跳重定向、跨 host 凭据剥离 | `internal/security/ssrf.go`；`core.URLGuard` | `internal/security/security_test.go` SSRF 矩阵；`http_test.go:TestProbeBlockedBySSRF` |
| §3 URL query / header / 错误详情脱敏 | `security.RedactURL` / `Redact` / `RedactHeaders`；`api.writeError` | `TestRedaction`；冒烟中 token 被写为 `***` |
| §3 DB 只存 `cred_ref` | `security.StripSensitiveHeaders` 在 store 两处强制剥离；API 三处写路径拒绝内联凭据头 | `TestSensitiveHeadersNeverPersisted`、`TestInlineCredentialHeadersRejected` |
| §4 PathGuard、`.part` 0600、原子 rename | `internal/security/path.go`、`internal/scheduler/chunkwriter.go` | `TestPathGuard`；`TestFullPipelineSingleFile` |
| `07` §1 远程鉴权 | `config.Validate` 拒绝「非回环 + 无 token」；daemon fail closed | `TestRemoteListenRequiresToken` |
| §1 Tampering（分片校验） | 每片 sha256 入 `checksums`，崩溃恢复按 `.part` 实际字节复验 | `TestCrashRecoveryResetsAndVerifies` |

**残余风险 / P0 明确不承诺**（登记于 [ADR-0020](adr/ADR-0020-P0实现基线与范围声明.md)，P1 前不得对外宣称已解决）：

1. **凭据不跨重启**：`MemoryCredentialStore` 是进程内参考实现，`mem://` 引用在 daemon 重启后失效，相关任务需重新提交凭据。系统钥匙串（Keychain / Credential Manager / libsecret）适配器尚未实现，`core.CredentialStore` 接口已预留。
2. **原始输入仍在内存**：`tasks.input` 落库前已 `RedactURL`，但进程内存中仍持有未脱敏的原始 `core.Input`（用于实际请求）；这是功能必需，需靠「不写日志 / 不进事件 / 不进响应」约束，而非靠删除。
3. **dev 模式是显式降级**：`security.allowLoopbackForDev` 会把回环目标从私网/端口黑名单中放开，仅允许在回环监听 + 本地联调时使用；`config.Validate` 禁止它与非回环监听组合。
4. **未覆盖面**：Metalink / m3u8 / 种子 / tracker peer 地址尚未解析，因此 §2 中针对这些来源的数量、大小、DTD 与分片上限尚无代码；插件沙箱、sidecar 隔离、遥测与崩溃上报同样未实现。**已补上**：许可证扫描、`govulncheck`、CycloneDX SBOM 与 `go mod verify` 由 `make gates` 执行并进入 CI（证据见 `17` §3）；但「高危漏洞 7 天内修复」的流程责任人、法务签字与 `THIRD_PARTY_NOTICES` 的对外发布形式仍待评审确认。
5. **工具链供应链**：Go 工具链已固定 1.27.3，但 CI 尚未固定构建镜像 digest，也未做可复现构建比对（`13` §12）；`GOTOOLCHAIN=auto` 依赖可用的 checksum DB，离线环境需预置工具链。
6. **鉴权仅 Bearer**：P0 无 TLS、无用户体系、无 CSRF/Origin 校验；非回环监听应置于受控网络或反向代理之后，且 `remoteToken` 必须足够随机。
