## 1. 安全目标与信任边界

**信任边界**：核心 Go 进程内为可信域；以下全部为**不可信输入**——用户提交的 URL / 种子 / Metalink / m3u8 / MPD、站点返回的 HTML 与流地址、插件脚本、重定向链、tracker 返回的 peer 列表、sidecar 输出 JSON。

| STRIDE | 主要威胁 | 控制 |
|---|---|---|
| Spoofing | 伪造 tracker / 镜像、DNS 重绑定 | TLS 校验、SSRF Guard、哈希校验 |
| Tampering | 分片被篡改、恶意 Metalink piece hash | 整文件 + 分块校验、`.part` 原子提交 |
| Repudiation | 任务来源与凭据使用不可追溯 | 脱敏审计事件（`events` 表） |
| Information Disclosure | Cookie/passkey/session 泄漏、日志脱敏失败 | 钥匙串、按任务最小化传递、`security.Redact` |
| DoS | 超大 XML、镜像爆炸、zip bomb、插件死循环 | 大小/数量/超时/内存上限、并发信号量 |
| Elevation | 插件调用 subprocess、提权助手被滥用 | 能力裁剪、WASM 隔离、独立授权 |

## 2. SSRF 防护规范（最高优先级）

Resolver 是本项目最大攻击面。所有由不可信输入产出的 URL（含 Metalink 镜像、m3u8 分片、站点重定向、yt-dlp `formats[].url`）必须经 `security.SSRFGuard`：

| 规则 | 要求 |
|---|---|
| 协议白名单 | 只允许 `http / https / ftp / ftps / sftp`；禁用 `file://`、`gopher://`、`dict://` 等 |
| 地址校验 | **解析后校验 IP**，拒绝回环、私网、链路本地（`169.254.0.0/16`，含云元数据）、组播、保留段、IPv4-mapped IPv6 私网 |
| DNS 重绑定 | 一次解析、Pin 住已校验 IP 用于实际连接；禁止二次解析 |
| 重定向 | **逐跳校验**，最多 3 跳；跨 host 重定向重新走完整校验 |
| 端口 | 默认仅 80/443/21/22/990 等；非标端口需用户显式允许 |
| 数量与大小 | Metalink 镜像 ≤ 32、XML ≤ 4MiB、禁止 DTD/外部实体；m3u8 分片数上限 |
| 凭据 | 重定向到不同 host 时**剥离** Authorization/Cookie，防止凭据外泄 |
| **FTP 被动数据通道**（WBS 9） | EPSV/PASV 返回的地址是服务器可控的第二个 socket：必须是字面 IP、必须等于已 pin 的控制连接 IP、仍过私网/保留策略、端口 ≥ 1024；任一不满足返回 `E_RESOLVE_SSRF_BLOCKED`。**禁止**信任 PASV 响应里的主机 |
| 失败 | 返回 `E_RESOLVE_SSRF_BLOCKED` 并记审计事件，不重试 |

## 3. 凭据管理

| 数据 | 存放 | 规则 |
|---|---|---|
| Cookie / Authorization / 代理密码 | 系统钥匙串 | SQLite 只存 `credential_ref`；按任务最小集合传递；任务结束释放 |
| PT passkey | 钥匙串 | **不进日志、不进事件、不跨任务同步**；announce URL 在内存中拼接 |
| Telegram session | 文件 0600 | 加密存储；`FLOOD_WAIT` 与会话失效需重新授权流程 |
| eD2k RSA 身份 | 文件 0600 | 必须持久化，否则重启换身份、积分归零 |
| Sidecar | — | 不继承核心环境变量；不共享全局凭据；工作目录限于下载目录 |

日志、事件、错误详情、`/tasks` 响应统一经过 `security.Redact`；PR 评审清单包含「新增日志字段是否可能含敏感值」。

**FTP / SFTP 凭据格式（WBS 9）**：`POST /api/v1/credentials` 的 `value` 为一个 JSON
**字符串**，字段 `username` / `password` / `private_key`（PEM）/ `passphrase` /
`host_key`（authorized_keys 行）/ `host_key_fingerprint`（`SHA256:...`）。
任务只携带 `credentialRef`；URL 中的 `user:pass@` 一律拒绝（§2）。FTP 无 ref 时匿名登录；
**SFTP 必须有 ref，且必须有 `host_key` 或 `host_key_fingerprint`**，缺失即在握手前失败
（fail closed，代码中不存在跳过主机密钥校验的分支）。凭据解析失败的错误文本不回显
密钥库诊断，避免二次泄漏。

## 4. 文件系统安全

- `ResourceFile.Path` 必须经 `PathGuard`：拒绝绝对路径、`..` 穿越、符号链接逃逸、Windows 保留名、超长路径。
- 输出统一写 `<target>.part`，校验通过后核心原子 `rename`；临时文件权限 0600。
- 磁盘预检：所需空间 ≥ 输入 + 输出（后处理约 2×）；空间不足返回 `E_STORAGE_FULL` 而非 OOM。
- 删除任务带 `withFiles` 时限定在任务输出目录内，禁止递归到任意路径。
- `thunder://` 解码结果必须重新校验 scheme 与 URL 合法性，禁止直接拼接执行。
- **已落地（WBS 8）**：`wrapper.go` 对解码结果复检 scheme / 内嵌凭据 / 控制字符并再过 SSRF Guard；
  `metalink.go` 对 `validateDocument` 产出的每个 `Mirror` 先做 `validateMirrorURL`、再调
  `guard.Check(ctx, url)`，任一失败即拒绝整个清单；`ResolveContext.Ctx` 为 nil 时回退
  `context.Background()`，避免把 nil 传给 Guard。

## 5. 插件与 sidecar 隔离

- goja 插件默认无 `fs` / `env` / `subprocess`；网络只能走宿主注入的白名单 `ctx.http`（详见 `08`）。
- 第三方规则包必须 Ed25519 签名校验；需要硬隔离时用 wazero/Extism 裁剪 WASI 能力。
- sidecar 通信走 stdin/stdout JSON-RPC，不占端口、无网络鉴权面；超时强杀；崩溃自动重启上限 3 次。
- **插件/sidecar 不得自行下载或写最终文件**；yt-dlp 只吐 JSON，ffmpeg 只读本地文件。
- 提权助手独立进程、单独分发、默认不安装，每次提权操作需显式用户授权。

**插件隔离实现矩阵（2026-11-10 WBS 10 落地）**：规范本身不变，下表记录 `internal/plugin/` 的实际控制点与自动化证据（详见 `08` §10）。

| 控制点 | 实现 | 证据 |
|---|---|---|
| 能力默认全关 | `manifest.go:Validate()` 对 `fs`/`env`/`subprocess` 为真直接拒绝加载；`ctx` 只注入 `http`/`log`/`base64`/`sha256`；goja 本身无 `require`/`process`/`globalThis` 宿主能力 | `plugin/runtime_test.go::TestRuntimeHasNoFsEnvOrSubprocess`、`manifest_test.go::TestParseManifestRejectsInvalid` |
| 第三方脚本静态扫描 | 加载期拒绝 `async/await`、`import`、`require`、`fetch`、`eval`、`Function()`、`__proto__`/`constructor`、`Deno`、箭头函数、可选链、模板字面量等；扫描前抹除注释/字符串/正则字面量以免误判 | `plugin/scan_test.go::TestScanRejectsForbiddenSyntax`、`TestScanIgnoresStringsCommentsAndRegexes` |
| Ed25519 签名 | 规则包按 `SHA256(canonicalManifest ‖ 0x00 ‖ script)` 签名；无签名 / 无受信公钥 / 公钥不匹配 / 脚本被改一律 fail-closed；仅 `plugins.insecure`（限回环监听）可跳过 | `plugin/signature_test.go::TestSignVerifyRoundTrip`、`manager_test.go::TestManagerRejectsUnsignedAndBadPacks` |
| 网络出口与逐跳校验 | `ctx.http.get` 逐个重定向跳校验 `allowedHosts` + `security.SSRFGuard`；手动跟随重定向（`http.ErrUseLastResponse`），敏感请求头禁止设置；`maxResponseBytes` 在 `Content-Length` 与读取两层拦截 | `plugin/runtime_test.go::TestRuntimeWhitelistBlocksRequests` / `TestRuntimePrivateURLBlockedByGuard` / `TestRuntimeRedirectHopIsWhitelisted` / `TestRuntimeOversizedResponseRejected` |
| 产出 URL / 路径校验 | 每个镜像 URL 过白名单 + SSRF Guard、每个输出路径过 `PathGuard`、剔除凭据头、拒绝未知摘要算法；插件只能填白名单字段，不能指定 engine / 凭据 / 状态 | `plugin/runtime_test.go::TestRuntimeOutputValidation`、`http_test.go::TestGuardBlocksProducedMirrorEvenWhenWhitelisted` |
| DoS | `vm.Interrupt` 看门狗按 `timeoutMs` 强杀死循环 → `E_RESOLVE_FAILED`；`memoryMB` 约束宿主可见分配与调用栈深度；目录内规则包数量与文件大小均有上限 | `plugin/runtime_test.go::TestRuntimeInfiniteLoopKilledByTimeout` / `TestRuntimeOutputBudgetAndNonObject`、`manager_test.go::TestFingerprintAndPluginDirsLimits` |
| 内置优先级 | 插件位于协议专属内置之后、通用 `direct-http` 之前；加载期拒绝与 `thunder`/`magnet`/`ed2k` 等哨兵冲突的 `match` | `app/daemon_test.go::TestPluginResolverPlacementInChain`、`plugin/manifest_test.go::TestParseManifestRejectsInvalid` |
| 规则失效与热更新 | `RULE_OUTDATED` → `E_CAPABILITY_UNAVAILABLE` + 兜底 Resolver，不静默丢任务；热更新失败保留上一份可用快照 | `plugin/manager_test.go::TestManagerFallbackOnRuleOutdated` / `TestManagerKeepsLastGoodVersionOnBadUpdate` |

**新增已知限制（不构成安全绕过，但必须如实披露）**：① goja 是**纯 JS 软隔离**，无 per-VM 堆上限，`memoryMB` 只约束宿主可见分配；真正硬隔离需按 ADR-0014 §5 升级 `wazero` / `Extism`。② 官方规则仓库、发布流水线与签名密钥轮换流程尚未建立，当前 `plugins.trustedKeys` 由本地配置/环境注入。③ 规则失效遥测默认关闭且**未实现**，当前仅在 daemon 日志中记录（不含 URL 与凭据）。④ 回放测试全部离线，真实站点 L4 互操作矩阵仍未执行。

## 7. 平台条款与法律边界（必须写进产品）

| 项 | 立场 |
|---|---|
| **私有 tracker** | 不承诺准入；保持诚实 PeerID，**禁止伪装** qBittorrent/Transmission 白名单身份；需要 PT 时做 BYO 适配器把任务交给用户已安装的白名单客户端（qBittorrent WebUI）。**WBS 7 落地**：私有种子强制 `NoDHT=true` / `DisablePEX=true` / `NoUpload=true` / `Seed=false`（BT-08）；PeerID 由 `-UD0000-` 前缀 + 6 随机字节诚实标识（ADR-0017），不伪装为流行客户端 |
| **迅雷 P2SP** | 私有协议，仅做链接解码；产品不得出现「迅雷加速」「高速通道」「离线下载」 |
| **DRM** | 明确不碰 Widevine / FairPlay / PlayReady；不提供规避技术措施的能力 |
| **视频站 / yt-dlp** | 能力限定为「下载用户有权保存的内容」；遵守站点 ToS 与 robots；不提供会员内容绕过；不内置账号共享 |
| **微信视频号** | 涉及逆向、MITM CA、JS 注入与平台条款；作为单独分发、默认不安装的可选插件，权限与风险与主程序物理隔离 |
| **Telegram** | 遵守 MTProto 与平台限速；`FLOOD_WAIT` 必须退避，不做规避限速的多账号滥用 |
| **eD2k / BT** | 明确做种义务与反吸血礼仪；不做 PeerID 伪装、不做假进度。**WBS 7 落地**：BT 走 `internal/transport/bt`（anacrolix/torrent，ADR-0004），做种默认关闭（`Seed=false`）、不伪装、metadata 仅经 BEP 9 扩展从直连对等点获取，远端 `*.torrent` 改由 `DirectFile` 负责 |
| **App Store / Play** | iOS 不得派生子进程或下载可执行代码；Android 不得 exec 应用私有目录文件；按需下载 sidecar 仅在桌面启用 |

### 7.1 BT / 磁力安全控制（WBS 7，2026-11-10）

`internal/transport/bt` 的每条安全控制映射到 `14` §11 序 4 交付边界与 ADR-0004 / ADR-0017：

| 控制 | 实现 | 对应条款 |
|---|---|---|
| 私有种子禁 DHT/PEX | `clientConfig`：`NoDHT = Private`、`DisablePEX = Private` | BT-08、R-11（PT 礼仪） |
| 默认不做种 | `NoUpload = true`、`Seed = false` | ADR-0004、R-10（规避吸血判定） |
| 诚实 PeerID | `-UD0000-` + 6 随机字节，不伪装为 qBittorrent/Transmission | ADR-0017、`07` §7 私有 tracker |
| tracker 仅透传、不二次请求 | Resolver 注入 `Trackers`；远端 `*.torrent` 由 `DirectFile` 取，Resolver 不发起二次网络 | `14` 序 4 边界 |
| metadata 仅经 BEP 9 直连 | 元数据从直连对等点扩展获取，不做 DHT/PEX 索引 | 同上 |
| 私网/端口仍过 SSRF Guard | 注入的 bootstrap 对等点地址经 `core.URLGuard` 校验 | §2 |
| 字节流受 Budget 约束 | `readWithBudget` 逐块计费回 `core.Budget`，与 HTTP/FTP 一致 | `04` 单调度器 |

### 7.2 MPL-2.0 合规（WBS 7，2026-11-10）

`anacrolix/torrent` 及其 `anacrolix/*` 传递依赖均为 MPL-2.0，与根 `LICENSE` 同许可。**本项目未修改任何 MPL 源文件，修改清单为空**，不触发 MPL §3.1 源提供义务；随发布附 `LICENSE` 与 `THIRD_PARTY_NOTICES.md` 即合规。详见 `10` §4 / §8.1。`make gates-strict` 许可证扫描在 WBS 7 后报 **86 个链接模块、0 左版、0 未识别**（WBS 10 后为 **90 个、0 左版、0 未识别**，见 `10` §8.2）。

## 8. 隐私

- 遥测**默认关闭**，需用户显式同意；只上报能力错误码与版本号，不上报 URL、文件名、凭据。
- 日志与事件保留期可配（默认 7 天）；`udctl backup` 导出不含凭据明文。
- 崩溃报告上传前经脱敏与用户确认。

## 9. 安全测试与响应

- `12` 的 SSRF 用例集、恶意 Metalink / m3u8 用例集、路径穿越用例集作为发布门禁。
- 依赖漏洞扫描（`govulncheck` + SBOM）纳入 CI；高危漏洞 7 天内修复或降级能力。
- 安全事件流程：发现 → 定级 → 修复/缓解 → 发布通告 → 复盘并更新本文档与 ADR。

**残余风险 / P0 明确不承诺**（登记于 [ADR-0020](adr/ADR-0020-P0实现基线与范围声明.md)，P1 前不得对外宣称已解决）：

1. **凭据不跨重启**：`MemoryCredentialStore` 是进程内参考实现，`mem://` 引用在 daemon 重启后失效，相关任务需重新提交凭据。系统钥匙串（Keychain / Credential Manager / libsecret）适配器尚未实现，`core.CredentialStore` 接口已预留。
2. **原始输入仍在内存**：`tasks.input` 落库前已 `RedactURL`，但进程内存中仍持有未脱敏的原始 `core.Input`（用于实际请求）；这是功能必需，需靠「不写日志 / 不进事件 / 不进响应」约束，而非靠删除。
3. **dev 模式是显式降级**：`security.allowLoopbackForDev` 会把回环目标从私网/端口黑名单中放开，仅允许在回环监听 + 本地联调时使用；`config.Validate` 禁止它与非回环监听组合。
4. **未覆盖面（2026-11-10 WBS 9 更新，WBS 7 已补）**：Metalink 清单与三种链接封装已于 P1 WBS 8 解析落地；FTP / FTPS / SFTP 传输已于 P1 WBS 9 落地，§2 中针对 FTP 被动数据通道的 IP pin、私网/端口校验，以及 §3 的凭据引用与主机密钥强制 pin **已有代码与回环自动化测试**；**BT / 磁力（WBS 7，2026-11-10）**：`resolve/magnet.go` + `resolve/torrent.go` + `transport/bt` 已落地，私有种子禁 DHT/PEX、默认不做种、诚实 PeerID、tracker 仅透传、metadata 仅经 BEP 9 直连获取，均有单元与回环真实协议集成测试（§7.1）。**插件沙箱（WBS 10，2026-11-10）**：`internal/plugin/` 已落地，`08` §10 / 本文 §5 列明能力裁剪、Ed25519 签名、静态扫描、逐跳 SSRF、产出校验、超时与热更新 fail-safe，全部有自动化测试；但 goja 为**软隔离**、规则仓库/发布流水线/遥测/WASM 硬隔离仍未具备。**仍不具备**：m3u8 / `lux` 站点解析、WASM 硬隔离、sidecar 隔离、遥测与崩溃上报、迅雷 P2SP、真实公网 BT 与真实站点互操作矩阵（§12 WBS 11）。**WBS 9 新增的已知限制**（不构成安全绕过，但影响性能/兼容性）：① 每个分片独立建立并登录一次会话（并发上限 8），未做连接池；② FTPS 数据通道的 TLS 会话未复用控制连接会话，个别要求 session reuse 的服务器可能拒绝；③ `MemoryCredentialStore` 仍是进程内实现，重启后 `mem://` 引用失效。**WBS 10 新增的已知限制**：见 §5 末尾四条。**已补上**：许可证扫描、`govulncheck`、CycloneDX SBOM 与 `go mod verify` 由 `make gates` 执行并进入 CI（**90 个链接模块，0 copyleft / 0 未识别**；证据见 `17` §3）；法务签字已由项目发起人 2026-11-09 全权批准（OPEN-01 定档 MPL-2.0，`LICENSE` 已入库）；但独立法务复核、`THIRD_PARTY_NOTICES` 的对外发布形式与「高危漏洞 7 天内修复」的流程责任人仍待 P1+ 确认。
5. **工具链供应链**：Go 工具链已固定 1.27.3，但 CI 尚未固定构建镜像 digest，也未做可复现构建比对（`13` §12）；`GOTOOLCHAIN=auto` 依赖可用的 checksum DB，离线环境需预置工具链。
6. **鉴权仅 Bearer**：P0 无 TLS、无用户体系、无 CSRF/Origin 校验；非回环监听应置于受控网络或反向代理之后，且 `remoteToken` 必须足够随机。
