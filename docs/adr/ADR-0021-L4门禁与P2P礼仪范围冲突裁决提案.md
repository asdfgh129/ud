## 背景（已核实事实）

### 2. WBS 7 的实现事实（2026-11-10 起未变）

- `internal/transport/bt/bt.go:clientConfig` **硬编码** `cfg.NoUpload = true`、
  `cfg.Seed = false`；私有种子另加 `NoDHT` / `DisablePEX`。PeerID 为
  `-UD0000-` 前缀（ADR-0004 实现落地段已记录）。
- 全仓**没有**上传槽、分享率 / `seed-time` 策略、UPnP/NAT-PMP 端口映射，
  也没有把 `uploaded/downloaded/left` 统一写入 `tasks.bytes_*` 的做种统计链路。
- `internal/config/config.go` 把 `BTConfig` 标为
  `Reserved groups: parsed for forward compatibility, ignored by P0`；
  `config.example.yaml` 同样写「P1+ 预留，P0 只解析不生效」。**P1 WBS 7 已交付 BT，
  但这些键至今仍未接入**——`13` §7 的示例配置与注释会让人误以为它们已生效。
- 因此 `BT-02`（我方做种）、`BT-11`（分享率 / seed-time）恒 `UNSUPPORTED`，
  `BT-03` 的「我方做种 → 对方下载」半向不可达；`make interop` 的 L4 为
  **0/14 PASS**，`release_gate_met: false`，`make interop-gate` 明确失败。

### 3. 现有登记的误归属（本提案要纠正的核心）

`12` §3.1「L4 门禁可满足性冲突」、`14` §11 续包补记、`03` §9 追踪矩阵、
`11` §10、`16` 卷首注与 ADR-0004 实现落地段，均把现状表述为
「**按 ADR-0004 不做种边界**」或「ADR-0004 的 `NoUpload=true` / `Seed=false`」。
**这与 ADR-0004 原文不符**：ADR-0004 说的是「库默认 `Seed=false`，因此**须自行实现**
做种策略」，并未把不做种确立为产品边界；ADR-0017 更把保持默认判为否决方案。

按 `15` §4 规则②「与已批准 ADR 冲突的实现视为缺陷」，正确定性是：

> **序 6 阻塞 = ① 实现相对已批准 ADR 与 M 级需求的未签署范围缩减（合规差距），
> ② 该缩减与 14/14 PASS 判据的形式冲突，③ 真实实验室条件缺失。三者并存，
> 且 ① 是根因。** 仅补齐真实客户端与千兆内网（解决 ③）无法关闭序 6；
> 仅修订 `12` §3.1 判据（解决 ②）也无法消除 ①。

由此，`12` §3.1 原处置路径 1「修订判据（保持产品边界，推荐）」**单独执行是不够的**：
若选择把不做种定为产品边界，必须同时处理 ADR-0004 / ADR-0017 与 `03` 的 M 级需求，
否则会留下「已批准决策要求做种、实现与判据却豁免做种」的未裁决矛盾。

## 决策（待评审裁决，本提案不生效）

**D1 · 定性**：把上述三点分别登记，且以 ① 为根因；现有文档中「ADR-0004 不做种边界」
的措辞属**误归属**，以追加「时点口径 / 阻塞校准」注的方式纠正，不改写已签署证据与
历史版本说明里的数值。

**D2 · 三条互斥裁决路径及各自必须变更的范围**（评审组须显式选择其一并签署）：

| 路径 | 内容 | 必须同步变更（缺一不可） | 代价 / 后果 |
|---|---|---|---|
| **A 补齐实现** | 实现受限做种 / 上传、分享率与 `seed-time`、上传槽、UPnP/NAT-PMP、统一 announce 统计，接通 `bt.*` 配置键 | 新增 P1 工作包 + `03` 追踪矩阵 + `05` 状态机落地 + `07`/`13` 配置生效 + `11` §7.1 + 重评 `14` R-10 吸血风险 + 全量 L4 与 NFR-PERF-01 | 代码回到 ADR 基线、判据不改；但属于**新功能范围**，需重做安全与礼仪评审，工作量最大 |
| **B 修订范围** | 把「v1 仅下载、不做种」正式定为产品边界 | ADR-0004 / ADR-0017 标 `Superseded by ADR-0021`（或附经批准的修订附录）、`03` FR-INT-01/04/FR-TRN-05 降级或改写、`01` 章程、`12` §3.1 判据改为「适用用例全 PASS + 非目标用例经签署显式豁免」、`14` §11 收口条件、`05` 状态机、`07`/`13` 配置键、`11` §7.1、`16` §4/§7 文案 | 范围与判据一致；但**必须**有可追溯的评审签署证据，且 `BT-02`/`BT-11`/`BT-03` 半向只能记「豁免」，**永远不得记为 PASS** |
| **C 保持开放** | 不改任何决策或判据 | 仅在 `14` §11 明确「阻塞源自合规差距 + 判据冲突，而非仅环境缺失」 | `release_gate_met` 恒 `false`、序 6 永不关闭；**不得以默认状态冒充已处置** |

**D3 · 本提案不代为裁决**：A 与 B 的取舍涉及产品定位、R-10 反吸血风险与法务口径，
须由 `docs/README` §一状态机与 `15` §4 规定的评审组签署。评审结论（含签署人、日期、
所选路径、豁免清单）必须作为可追溯证据入库，并在 `docs/adr/README.md` 索引中把本 ADR
从 `Proposed` 改为 `Accepted` / `Rejected`（`15` §4 规则④）。

## 后果

**正面**：阻塞性质被准确定档；评审组拿到可直接签署的选项与完整影响面清单；
`13` §7 / `config.example.yaml` 的「配置看起来已生效」误导被消除；L4 实验室
可执行链路（`make l4-preflight` / `make l4-run`，见 `12` §3.1.3）与阻塞定档分离，
条件齐备时可立即产出真实证据。

**负面 / 约束**：在签署前，序 6 仍不能关闭，`release_gate_met` 恒 `false`；
若选 B，需承认 v1 与 ADR-0004 / ADR-0017 原始决策存在范围缩减，并在 `16` §7
对外文案中保持「兼容标准 BitTorrent 网络，可与主流客户端互通」，
**不得**写「已与主流客户端实测互通」「全矩阵通过」「千兆内网性能达标」。
