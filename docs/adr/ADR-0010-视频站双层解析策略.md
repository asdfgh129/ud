# ADR-0010 视频站双层解析：lux 进程内 + yt-dlp 仅吐 JSON

- **状态**：Accepted（2026-11-09 P0 里程碑评审批量批准）
- **日期**：2026-11-08
- **决策者**：架构组
- **关联**：`04` §6、`09` §7、`03` FR-SRC、`14` R-03/R-04

## 背景

追问「视频网站能否直接用 Go 改写、完全不引入 sidecar」。核实结论：**技术上能，但换来的不是「去掉 sidecar」，而是「接手一条维护流水线」**。

- `lux`（Go / MIT）覆盖几十个站点，中文站（B 站 / 抖音 / 优酷 / 微博）比 yt-dlp 更上心，且可直接 import 为 Go 库；配 `goja` 声明式规则插件即可完全进程内 + 规则包热更新。
- 但 yt-dlp 的护城河**不是 Python，是 1000+ extractor + 社区近每日修复**；lux 维护节奏偏慢（README 自列优酷/西瓜已知问题，2026 年中曾数月无提交）。
- **YouTube 是硬骨头**：2025-11 起需 JS 运行时解 `n` 参数 / sig（EJS），上面还叠着 PO token、SABR、attestation 的持续对抗。纯 Go 要么 `goja`（ES5.1，常跑不动现代挑战脚本），要么 `wazero` + QuickJS-WASM（工程量大），要么仍用 Deno。**JS 引擎可以进进程，站点对抗逻辑没法一劳永逸。**

## 决策

1. **双层策略**：
   - 中文站 + 有限长尾 → `lux` + `goja` 规则插件，**进程内纯 Go**，规则包独立热更新；
   - YouTube / 千站长尾 → `yt-dlp` sidecar（Python worker），**只做解析**。
2. **yt-dlp 只吐 JSON，绝不自己写文件**：`-J --skip-download`，产出 `formats / url / http_headers / cookies`，流地址交回核心 HTTP/HLS 引擎。禁止 `--downloader aria2c`（已无该依赖）与任何自行落盘行为，否则进度/限速/断点/队列被割裂成两套，统一 `Resource` 模型白做。
3. **Deno 2.3+（或 Node 22+）作为 yt-dlp 的子依赖**随包或按需提供，仅作 EJS 求解器，不参与数据传输；需带 `yt-dlp[default]` 的 EJS 脚本并校验完整性。
4. **格式选取逻辑由我方实现**：直接从 `-J` 的 `formats` 选择合适流，规避「yt-dlp 检测不到 ffmpeg 自动退化到 `-f best/bv*+ba`、只挑 progressive 格式，YouTube 上通常只有 720p 或更低」的画质陷阱；高画质分离流由自有 HTTP 引擎下两条 + 自有 Remux 合并（ADR-0011）。
5. 规则包与 yt-dlp 走**独立更新通道**，与主程序发版解耦；规则失效属常态维护，必须给用户可读提示并允许兜底 Resolver，不得静默失败。
6. 不自行实现 YouTube 对抗（PO token / SABR / attestation）。

## 备选方案

| 方案 | 结论 |
|---|---|
| 全量用 Go 重写 yt-dlp | ❌ 等于把「一个 sidecar 依赖」换成「一个长期维护站点规则的团队」 |
| 用 goja 硬扛 YouTube 现代 JS 挑战 | ❌ ES5.1 常不足；且对抗逻辑持续变化 |
| 只保留 lux，放弃 YouTube | 若产品明确不做 YouTube 则可选，此时可达**零 sidecar** |
| 让 yt-dlp 直接下载/合并 | ❌ 撕裂统一调度与进度模型 |

## 后果

**正面**：中文站零 sidecar 且规则热更新；长尾能力交给社区；画质不受 ffmpeg 缺失影响；架构只需 `Resolver` 接口，不为 yt-dlp 提前让步。

**负面**：做 YouTube 时必需 sidecar 为 2（yt-dlp + Deno）；站点规则失效是持续运维负担（R-03）；YouTube 对抗升级时能力可能临时不可用（R-04），需要明确降级而非静默。

## 合规与验证

- CI 用录制回放 fixture，禁止直连真实站点（`12` §1）。
- 集成测试：删除 ffmpeg 后仍能拿到 1080p 格式并完成合并（`12` §6）。
- 抓包/日志验证 yt-dlp 未写最终文件、未拉流；Deno 仅被 yt-dlp 调用。
- 能力限定为下载用户有权保存的内容，不提供会员/DRM 绕过（`11` §7）。
