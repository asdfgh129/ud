# ADR-0016 核心为 daemon，UI 用 Flutter/Tauri 且可替换

- **状态**：Accepted（2026-11-09 P0 里程碑评审批量批准）
- **日期**：2026-11-08
- **决策者**：架构组 + 客户端
- **关联**：`04` §3.2/§7、`07`、`13` §6、OPEN-02

## 背景

下载任务需要在 UI 关闭后继续、需要被远程/第三方前端接管、需要在 headless 环境运行；同时移动端不能派生子进程。这要求核心与 UI **物理分离**，但移动端又必须把核心链接进同一 App。

## 决策

1. 核心为**常驻 Go daemon**，通过 REST + WebSocket（可选 JSON-RPC）对外暴露；UI / CLI / 浏览器扩展 / AriaNg 都是可替换客户端。
2. 桌面：daemon 进程 + UI 客户端，本机回环监听（`127.0.0.1:0` 随机端口 + 本地发现文件），**不占用固定 6800 端口**；远程访问需显式开启 + token。
3. 移动端：核心**以库形式链接进 App（同进程、不派生子进程）**，UI 直连内部接口；禁用所有 sidecar。
4. UI 框架候选 **Flutter**（一套覆盖 Win/macOS/Linux/Android/iOS/Web，Gopeed 已验证）或 **Tauri**（更轻）；最终定档为 `OPEN-02`，P0 结束前决定（已于 2026-11-09 定档 **Flutter**，见 `14` §7 / `17` §8）。**框架选择不得影响核心 API 契约**。
5. 对外接口可对齐 aria2 RPC 以复用生态（L1，见 ADR-0019），但那是**控制面兼容**，与 P2P 线协议无关。

## 备选方案

| 方案 | 结论 |
|---|---|
| 把 UI 与核心做成同一进程（桌面） | ❌ UI 关闭即停下载；无法 headless / 远程 |
| Electron 做核心 | ❌ 体积大、不适合下载内核（仅 UI 备选） |
| 移动端起 daemon 子进程 | ❌ iOS 禁止派生子进程、Android W^X |
| 固定 6800 端口 | ❌ 端口冲突、多实例问题、沿用 aria2 运维包袱 |

## 后果

**正面**：UI 可替换、可远程、可 headless；移动端与桌面共享同一核心代码；第三方前端生态可复用；无端口与进程监督负担。

**负面**：桌面需要进程间契约与本地发现机制；移动端「同进程链接」与桌面「独立进程」两种形态需要构建矩阵区分（`13` §2）；Flutter/Tauri 定档前客户端排期有不确定性。

## 合规与验证

- `07` 契约测试覆盖 REST/WS/CLI 三类客户端；`12` L5 端到端覆盖「UI 关闭后任务继续」。
- 移动端产物中无 daemon 可执行文件、无 sidecar（`12` 发布门禁）。
- `CGO_ENABLED=0` 六平台 + gomobile 构建通过。
