# 16 互操作性与兼容性设计

> 文档编号：UD-DOC-16 ｜ 版本：v0.2 ｜ 状态：草案（产品文案需法务会签） ｜ 日期：2026-11-10 ｜ 相关：ADR-0004、ADR-0005、ADR-0017、`12` §3

> **v0.2 说明**：P1 WBS 8 于 2026-11-10 交付链接解码与 Metalink 清单解析；§7 文案口径不变且仍然强制，§8 补记实际能力边界。真实互操作回归套件（§6）仍为 P1 后续工作包。

## 1. 三层判据

「协议库能跑」与「能被现有网络接纳」是两件事，必须分三层评估：

| 层 | 问题 | 结论 |
|---|---|---|
| ① 线协议层 | 握手、消息、分片、tracker 报文字段是否互通 | **基本完全兼容** |
| ② 会话与身份层 | PeerID、private flag、做种、积分、端口可达 | **需要我们在 P0 起显式实现** |
| ③ 网络准入层 | 私有 tracker 白名单、社区规则、生态反吸血 | **代码解决不了，也不该硬闯** |

## 2. BT 线协议覆盖

`anacrolix/torrent` v1.61.x 官方 BEP 清单：**3 / 4 / 5 / 6 / 7 / 9 / 10 / 11 / 12 / 15 / 19 / 20 / 23 / 27 / 29 / 40 / 41 / 42 / 43 / 47 / 52 / 54 / 55**，另含 MSE/PE 加密、uTP、WebTorrent(WebRTC)、WebSeed、BT v2 混合种子、打洞、智能封禁、IPv6、HTTP/UDP tracker 客户端与服务端、scrape。2014 年起生产使用，Gopeed / bitmagnet / TorrServer 等在运行。

| 对象 | 判定 |
|---|---|
| qBittorrent / Transmission / libtorrent 系公网 peer（双向做种与下载） | ✅ 无阻碍 |
| 公开 HTTP / HTTPS / UDP tracker、compact peer list、多 tracker 分层、IPv6 扩展、scrape、passkey（只是 announce URL 的一部分） | ✅ 协议层通 |
| `private=1`（BEP 27） | ✅ 库已实现，需我方确保关闭 DHT/PEX/LSD |
| **LSD（BEP 14，局域网组播发现）** | ❌ 库未实现（issue #248 自 2018 未合）；需自补几十行组播或依赖 tracker/DHT |
| **Super-seeding（BEP 16）** | ❌ 库未实现 |
| **BT v2** | ⚠️ 只使用 **hybrid**；v1-only 客户端无法加入纯 v2，tracker 对 `btmh` / 双 infohash 双 announce 支持仍不整齐，部分实现明确把「与 libtorrent/qBittorrent v2 live 互操作」列为未完成 → 产品默认 v1/hybrid |
| 迅雷 P2SP | ❌ 私有协议，仅 `thunder://` 解码 |

## 3. eD2k 线协议覆盖

`goed2k`（MIT，v0.1.0，Gopeed v1.9.3 采用）实现：多 eD2k 服务器 + `server.met`、Kad4/KadV6 bootstrap 与搜源发布、Source Exchange、Low ID 回调、AICH、Secure Ident（RSA 2048）、**积分系统**（`PeerCreditManager` / `ScoreRatio` / `client_credits.go`）、zlib 上传压缩、OfferFiles / Kad 发布、CryptLayer 协议混淆、Collection 链接。aMule/eMule 主要互通路径基本覆盖。

## 4. 会话与身份层：必须显式实现的事项

| 项 | 库默认 / 现状 | 我方动作 |
|---|---|---|
| PeerID / 客户端身份 | `-GT0001-` + 扩展握手 `go.torrent dev 20150624`；`Bep20` / `PeerID` / `ExtendedHandshakeClientVersion` 可配 | **保持诚实身份，禁止伪装 qBittorrent** |
| private flag | 库已实现 | `private=1` 关闭 DHT/PEX/LSD；passkey 不进日志、不跨任务同步 |
| **做种** | `Seed` **默认 false**，默认只为换回数据而上传；`NoUpload` 开着即纯吸血 | 显式实现分享率/时长策略、上传槽、UPnP/NAT-PMP 端口映射；否则 PT 上 H&R、公网上被反吸血工具盯上 |
| announce 统计 | 需要精确的 `uploaded/downloaded/left` | **从统一 Task 模型取数**（`tasks.bytes_*`），禁止各 Transport 自算 |
| `Resource` 模型 | 若只含 URL/Header/大小 | **P0 一次性加入**：v1 infohash / v2 btmh、private flag、tracker 分层、passkey ref、peer_id；eD2k 的 file hash / AICH root / UserHash / 持久 RSA 身份 / clients.met 积分（ADR-0013） |
| **goed2k 默认开关** | 混淆 CryptLayer **默认关**、Secure Ident **默认关**、`CreditsOnlyVerified=false` | 真实网络应**开启混淆**（部分客户端设为「仅混淆」会拒绝明文）与 SecIdent，并持久化 RSA 身份（PEM 0600），否则重启换身份、积分归零 |
| Low ID | 有回调与 UPnP | 需 TCP 4662 / UDP 4672 可入站；否则只能看到约 40–60% 源、无法连其他 Low ID；维护 `server.met` 与 Kad `nodes.dat` 引导列表 |

> 控制面兼容（L1 aria2 RPC facade 让 AriaNg / 浏览器扩展能连我们）属于**控制面**，与 P2P 线协议兼容是两回事，不得混为一谈。

## 5. 网络准入层：不由代码决定

### 5.1 私有 tracker
PT 普遍只白名单 qBittorrent / Transmission / rTorrent / Deluge 等特定版本，靠 PeerID + 扩展握手识别；未列入白名单的 `-GT0001-` 会被拒或标记。伪装 PeerID 违反站点规则，且 announce 时序、格式、统计交叉校验容易被反作弊识别。

**产品决策**：只声明「兼容标准 BT 网络，**不承诺 PT**」；确有需求时提供可选 BYO 适配器，把任务交给用户已安装的白名单客户端（qBittorrent WebUI），而非自己冒充。公网侧也有 PeerBanHelper 类按 PeerID/Client Name 黑名单 + 伪装检测 + 假进度检查的工具，诚实做种能缓解但无法保证。

### 5.2 eMule 网络现实
「能连上」≠「下得动」：积分是**双向、按客户端对**计分，新客户端 modifier 恒为 1.0，排在上传队列末尾，须先给别人上传才能攒信用；网络规模小，冷门文件常无在线源；0.50a 与社区版 0.72a 并存，部分 mod 有「不良客户端检测」。

**最大技术风险**：`goed2k` 为 AI 辅助开发的 v0.1.0 新库，官方文档明确写「尚未与真实 eMule 全版本做大规模互操作回归；生产环境建议先小范围试连」。Gopeed 是一个生产用例，但不等于全版本验证 → 必须靠 §6 套件兜底。

## 8. 兼容性结论表

| 对象 | 判定 |
|---|---|
| qBittorrent / Transmission / libtorrent 等公网 peer | ✅ 双向互通 |
| 公开 HTTP/UDP/HTTPS tracker、scrape、passkey、private flag | ✅ 协议层通 |
| 私有 tracker 准入 | ⚠️ 技术可通、规则不接纳，**不承诺** |
| aMule / eMule 客户端 | ✅ 线协议通；⚠️ 速度受积分、Low ID、混淆、源数量支配 |
| HTTP / FTP / SFTP 镜像、Metalink 清单 | ✅ 标准协议 |
| 迅雷 P2SP / 高速通道 / 离线下载 | ❌ 私有协议，仅链接解码 |

**WBS 8 实现边界（2026-11-10）**：`thunder://` / `flashget://` / `qqdl://` 解码与 Metalink
v3/v4 XML、RFC 6249 头已落地为内置纯 Go Resolver，并有自动化测试（`12` §3.3）。
上表「HTTP / FTP / SFTP 镜像」中 **FTP / SFTP 的 Transport 仍未实现**，Metalink 清单里指向
这类 scheme 的镜像会在 `transport.Select` 处显式报能力错误；多 `<file>` 清单与远端
`.meta4` URL 抓取同样不支持。因此对外仍只能写「支持 Metalink 多源清单解析」，不得写
「完整 Metalink 生态」「迅雷加速」。
| DRM 内容 | ❌ 明确不支持 |
