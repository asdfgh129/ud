## 1. 三层判据

「协议库能跑」与「能被现有网络接纳」是两件事，必须分三层评估：

| 层 | 问题 | 结论 |
|---|---|---|
| ① 线协议层 | 握手、消息、分片、tracker 报文字段是否互通 | **基本完全兼容** |
| ② 会话与身份层 | PeerID、private flag、做种、积分、端口可达 | **需要我们在 P0 起显式实现** |
| ③ 网络准入层 | 私有 tracker 白名单、社区规则、生态反吸血 | **代码解决不了，也不该硬闯** |

## 2. BT 线协议覆盖

`anacrolix/torrent` v1.61.x 官方 BEP 清单：**3 / 4 / 5 / 6 / 7 / 9 / 10 / 11 / 12 / 15 / 19 / 20 / 23 / 27 / 29 / 40 / 41 / 42 / 43 / 47 / 52 / 54 / 55**，另含 MSE/PE 加密、uTP、WebTorrent(WebRTC)、WebSeed、BT v2 混合种子、打洞、智能封禁、IPv6、HTTP/UDP tracker 客户端与服务端、scrape。2014 年起生产使用，Gopeed / bitmagnet / TorrServer 等在运行。

| 对象 | 判定 |
|---|---|
| qBittorrent / Transmission / libtorrent 系公网 peer（双向做种与下载） | ✅ 无阻碍 |
| 公开 HTTP / HTTPS / UDP tracker、compact peer list、多 tracker 分层、IPv6 扩展、scrape、passkey（只是 announce URL 的一部分） | ✅ 协议层通 |
| `private=1`（BEP 27） | ✅ 库已实现，需我方确保关闭 DHT/PEX/LSD |
| **LSD（BEP 14，局域网组播发现）** | ❌ 库未实现（issue #248 自 2018 未合）；需自补几十行组播或依赖 tracker/DHT |
| **Super-seeding（BEP 16）** | ❌ 库未实现 |
| **BT v2** | ⚠️ 只使用 **hybrid**；v1-only 客户端无法加入纯 v2，tracker 对 `btmh` / 双 infohash 双 announce 支持仍不整齐，部分实现明确把「与 libtorrent/qBittorrent v2 live 互操作」列为未完成 → 产品默认 v1/hybrid |
| 迅雷 P2SP | ❌ 私有协议，仅 `thunder://` 解码 |

## 3. eD2k 线协议覆盖

`goed2k`（MIT，v0.1.0，Gopeed v1.9.3 采用）实现：多 eD2k 服务器 + `server.met`、Kad4/KadV6 bootstrap 与搜源发布、Source Exchange、Low ID 回调、AICH、Secure Ident（RSA 2048）、**积分系统**（`PeerCreditManager` / `ScoreRatio` / `client_credits.go`）、zlib 上传压缩、OfferFiles / Kad 发布、CryptLayer 协议混淆、Collection 链接。aMule/eMule 主要互通路径基本覆盖。

## 4. 会话与身份层：必须显式实现的事项

| 项 | 库默认 / 现状 | 我方动作 |
|---|---|---|
| PeerID / 客户端身份 | `-GT0001-` + 扩展握手 `go.torrent dev 20150624`；`Bep20` / `PeerID` / `ExtendedHandshakeClientVersion` 可配 | **保持诚实身份，禁止伪装 qBittorrent** |
| private flag | 库已实现 | `private=1` 关闭 DHT/PEX/LSD；passkey 不进日志、不跨任务同步。**WBS 7 落地（2026-11-10）**：`transport/bt.clientConfig` 对已标 `Private` 的 Resource 强制 `NoDHT=true` / `DisablePEX=true` / `NoUpload=true` / `Seed=false`（`11` §7.1），不做 LSD |
| **做种** | `Seed` **默认 false**，默认只为换回数据而上传；`NoUpload` 开着即纯吸血 | 显式实现分享率/时长策略、上传槽、UPnP/NAT-PMP 端口映射；否则 PT 上 H&R、公网上被反吸血工具盯上 |
| announce 统计 | 需要精确的 `uploaded/downloaded/left` | **从统一 Task 模型取数**（`tasks.bytes_*`），禁止各 Transport 自算 |
| `Resource` 模型 | 若只含 URL/Header/大小 | **P0 一次性加入**：v1 infohash / v2 btmh、private flag、tracker 分层、passkey ref、peer_id；eD2k 的 file hash / AICH root / UserHash / 持久 RSA 身份 / clients.met 积分（ADR-0013） |
| **goed2k 默认开关** | 混淆 CryptLayer **默认关**、Secure Ident **默认关**、`CreditsOnlyVerified=false` | 真实网络应**开启混淆**（部分客户端设为「仅混淆」会拒绝明文）与 SecIdent，并持久化 RSA 身份（PEM 0600），否则重启换身份、积分归零 |
| Low ID | 有回调与 UPnP | 需 TCP 4662 / UDP 4672 可入站；否则只能看到约 40–60% 源、无法连其他 Low ID；维护 `server.met` 与 Kad `nodes.dat` 引导列表 |

> 控制面兼容（L1 aria2 RPC facade 让 AriaNg / 浏览器扩展能连我们）属于**控制面**，与 P2P 线协议兼容是两回事，不得混为一谈。

## 5. 网络准入层：不由代码决定

### 5.1 私有 tracker
PT 普遍只白名单 qBittorrent / Transmission / rTorrent / Deluge 等特定版本，靠 PeerID + 扩展握手识别；未列入白名单的 `-GT0001-` 会被拒或标记。伪装 PeerID 违反站点规则，且 announce 时序、格式、统计交叉校验容易被反作弊识别。

**产品决策**：只声明「兼容标准 BT 网络，**不承诺 PT**」；确有需求时提供可选 BYO 适配器，把任务交给用户已安装的白名单客户端（qBittorrent WebUI），而非自己冒充。公网侧也有 PeerBanHelper 类按 PeerID/Client Name 黑名单 + 伪装检测 + 假进度检查的工具，诚实做种能缓解但无法保证。

### 5.2 eMule 网络现实
「能连上」≠「下得动」：积分是**双向、按客户端对**计分，新客户端 modifier 恒为 1.0，排在上传队列末尾，须先给别人上传才能攒信用；网络规模小，冷门文件常无在线源；0.50a 与社区版 0.72a 并存，部分 mod 有「不良客户端检测」。

**最大技术风险**：`goed2k` 为 AI 辅助开发的 v0.1.0 新库，官方文档明确写「尚未与真实 eMule 全版本做大规模互操作回归；生产环境建议先小范围试连」。Gopeed 是一个生产用例，但不等于全版本验证 → 必须靠 §6 套件兜底。

本次只交付「可复跑的套件骨架与本地回环子集」，并未执行真实网络互操作。已建立：
① `internal/interop/suite.go:Registry()` 按原序登记 14 条 L4 门禁用例，状态模型区分
`PASS` / `FAIL` / `SKIPPED` / `UNSUPPORTED`，`SKIPPED` 与 `UNSUPPORTED` 绝不计为通过；
② 自建 BEP 3 HTTP / HTTPS tracker（`httptest` + 自签证书、passkey、503 / 挂起故障注入、
多 tracker 分层降级、scrape）与 BEP 15 UDP tracker（IPv4 / IPv6、connect / announce / scrape、
BEP 23 compact peer 6B / 18B）——**这些是纯 Go fixture，不是 `chihaya` / `opentracker` 二进制**；
③ 9 条 `L3-xx` 回环自动化用例，覆盖真实 BT 线协议端到端（独立 seeder + `bttransport`）、
诚实 PeerID 握手抓包、纯磁力 BEP 9 元数据、多文件选择下载、流式首片时延；
④ `cmd/udinterop` + `make interop` / `make interop-gate`，产出 `dist/interop.json` /
`dist/INTEROP.md`，CI 跑 `make interop` 并上传证据；`--require-external --external-config`
预留真实客户端外部 harness。

**仍未执行 / 不得宣称**：真实 qBittorrent / Transmission / libtorrent 双向做种与下载、
`chihaya`/`opentracker` 二进制、`private=1` 的**抓包级** DHT/PEX/LSD 验证、BT v2 hybrid
真实客户端互操作、uTP / MSE / WebSeed 真实链路、LSD 与 Super-seeding（§2 库本身未实现）、
eD2k 组（`12` §3.2）、AriaNg L1 facade 验收、以及 NFR-PERF-01 千兆内网 1GiB ≥ 80MB/s 基准。
`make interop` 绿 = 本地自动化部分健康；发布结论只能取自 `dist/interop.json:release_gate_met`
（当前 `false`），`make interop-gate` 在门禁未满足时明确失败。

## 8. 兼容性结论表

| 对象 | 判定 |
|---|---|
| qBittorrent / Transmission / libtorrent 等公网 peer | ✅ 双向互通 |
| 公开 HTTP/UDP/HTTPS tracker、scrape、passkey、private flag | ✅ 协议层通 |
| 私有 tracker 准入 | ⚠️ 技术可通、规则不接纳，**不承诺** |
| aMule / eMule 客户端 | ✅ 线协议通；⚠️ 速度受积分、Low ID、混淆、源数量支配 |
| HTTP / FTP / SFTP 镜像、Metalink 清单 | ✅ 标准协议 |
| 迅雷 P2SP / 高速通道 / 离线下载 | ❌ 私有协议，仅链接解码 |
| DRM 内容 | ❌ 明确不支持 |

**WBS 8 / 9 实现边界（2026-11-10）**：`thunder://` / `flashget://` / `qqdl://` 解码与
Metalink v3/v4 XML、RFC 6249 头已落地为内置纯 Go Resolver；FTP / FTPS / SFTP 的
Transport 已于 WBS 9 落地，上表「HTTP / FTP / SFTP 镜像」中的三类镜像现在都能被
`transport.Select` 选中并实际下载（`12` §3.3 有回环真实协议栈用例）。
**仍不支持**：多 `<file>` 清单、远端 `.meta4` URL 抓取、FTP 主动模式、FTPS 数据通道
TLS session 复用、无 host key pin 的 SSH 连接；与真实公网 FTP/SFTP 服务器的互操作矩阵
尚未执行。因此对外仍只能写「支持 Metalink 多源清单解析」「支持 FTP / FTPS / SFTP 下载」，
不得写「完整 Metalink 生态」「兼容所有 FTP 服务器」「迅雷加速」。

**WBS 7 实现边界（2026-11-10）**：BT / 磁力已由 `internal/transport/bt` 落地（§4、
`11` §7.1），上表前两行从「协议层通」变为**代码已实现**：magnet 与 `.torrent` 解析、
公开 HTTP/UDP/HTTPS tracker 透传、private flag 关闭 DHT/PEX/LSD、`File.NewReader` 流式读、
选择下载均已具备单元与回环真实协议集成测试（anacrolix ↔ anacrolix，`12` §9）。
**明确边界**：① 私有 tracker 准入仍为「不承诺」，产品只写「兼容标准 BitTorrent 网络，
可与主流客户端互通」，不得写「支持 PT 站点」「兼容所有 tracker」；② 与真实
qBittorrent / Transmission / libtorrent 的 **L4 互操作矩阵（`12` §3.1 BT-01…BT-14）
尚未执行**，当前证据仅回环 fixture，不得据此宣称「已与主流客户端实测互通」；
③ 做种默认关闭（`Seed=false`），不提供分享率 / 上传槽 / UPnP 策略；④ 远端
`http(s)://*.torrent` 由 `DirectFile` 负责，BT Resolver 不发起二次网络请求。

**WBS 10 实现边界（2026-11-10）**：goja 声明式站点规则插件已由 `internal/plugin/` 落地
（ADR-0014、`08` §10）。**已具备**：`ud.plugin/v1` manifest 与加载期严格校验、ES5.1 静态禁用 API
扫描与 `export` 转译包装、Ed25519 规则包签名、能力默认全关（无 `fs`/`env`/`subprocess`）、
`ctx.http` 白名单 + 逐跳 SSRF Guard + 响应大小上限、产出 URL/路径/请求头校验、超时强杀、
`RULE_OUTDATED` 兜底、按目录指纹的独立热更新，以及 `udctl plugin` 离线开发与回放工具链。

**明确边界**：① **不承诺兼容 Node / Deno / 浏览器扩展脚本或现代 JS 语法**（goja 仅 ES5.1，
`async/await`、ES Module、`fetch`、箭头函数等在加载期被拒绝）；② **不承诺 WASM 硬隔离**
（wazero / Extism 为 ADR-0014 §5 未来升级路径），goja 为进程内软隔离且无 per-VM 堆上限；
③ 官方规则仓库、发布流水线、签名密钥轮换与规则失效遥测**未建立**，当前 `trustedKeys` 由本地
配置/环境注入；④ 回放测试全部离线录制，**与真实站点的 L4 互操作矩阵未执行**，不得宣称
「支持所有视频站」「站点规则开箱即用」；⑤ `lux` / `yt-dlp` 兜底与 sidecar 集成仍为 P2+。

**WBS 11 实现边界（2026-11-11）**：互操作套件 v1 已由 `internal/interop/` + `cmd/udinterop`
