## 3. 本轮补齐的客观门禁（`docs/14` §8 度量输出）

由 `tools/gates.py` + `make gates` 复跑，证据全部落在 `dist/`（生成物，`.gitignore` 忽略），汇总见 `dist/GATES.md` / `dist/gates.json`。

| 门禁 | 状态 | 实测结果 |
|---|---|---|
| CycloneDX SBOM + `go mod verify` | ✅ PASS | CycloneDX 1.6，从 `go version -m` 的**实际链接模块图**生成 12 个 component；附 `checksums.txt`、`build-metadata.txt`、`THIRD_PARTY_NOTICES.md`；`go mod verify` 通过 |
| 传输路径许可证扫描（NFR-LEG-01） | ✅ PASS | 12 个链接模块：BSD-3-Clause ×7、MIT ×3、BSD-2-Clause ×1、Apache-2.0 ×1；**0 GPL/LGPL/AGPL、0 未识别** |
| 依赖漏洞扫描（`12` §6） | ✅ PASS | 首次扫描发现真实告警 → 修复后复扫 `No vulnerabilities found`，详见 §4 |
| 回滚/降级路径演练（`12` §8 DoD） | ✅ PASS | `TestBackupRestoreRollbackDrill`：备份 → 模拟坏升级（`schema_version=2` + 分片清零）→ 恢复备份 DB → 重启后迁移幂等、`.part` 未变、仅哈希匹配的分片复用 |
| HTTP 吞吐回归基线（`12` §5） | ✅ PASS | `BenchmarkRangeThroughput`：32MiB / 4 连接 / 256KiB 分片，回环基线约 0.9–1.6 GB/s（随机器波动，仅用于同机回归对比） |
| 覆盖率阈值（`12` §1/§8） | ⚠️ WARN | 全仓 59.0%；`core` 92.9%、`security` 91.9% 达标；**其余 8 个包低于 80%**，见 §5 |

> **口径澄清**：`12` §1 写「`core`/`security` ≥ 90%」、§8 写「核心包 ≥ 80%（`security` ≥ 90%）」，两处不一致。v0.3 已统一为：`core`/`security` ≥ 90%，其余 P0 关键路径包 ≥ 80%，`cmd/*` 与 `internal/version` 只报告不设门禁。`WARN` 是真实的未达标项，**不是通过**。
>
> **基准口径**：回环吞吐是回归基线，**不能替代 NFR-PERF-01**（千兆内网 1GiB ≥ 80MB/s）；L4 互操作、1000 任务长稳、故障注入全套仍属 P1+，不得据本次结果宣称达标。

## 4. 本轮发现并修复的真实缺陷

| # | 缺陷 | 影响 | 处置 |
|---|---|---|---|
| 1 | `govulncheck` 报 `GO-2026-6809`：Go 1.27.2 标准库 `crypto/x509` 不再信任被入侵的中间 CA，调用链经 `store.WholeFileChecksum → io.Copy → x509.Certificate.Verify` 可达 | **安全**，影响 TLS 下载链路 | `go.mod` 与 CI 升到 Go 1.27.3；重跑 `govulncheck` 干净；见 `CHANGELOG.md` `Security` |
| 2 | `core.EventBus.Dropped()` 是文档化的诊断计数，但 `Publish` 从未累加 | 慢 WebSocket 客户端丢事件不可观测 | 改 `atomic.Int64` 累加（Publish 只持读锁，用 mutex 计数会数据竞争）；补 `TestEventBusDroppedCounterAndClose` |
| 3 | 覆盖率依赖 `TestULID` 的「同毫秒」时序，全量并行跑时在 89.4%–92.4% 之间抖动 | 门禁不可复现 | 补确定性 `TestIncrementEntropyCarry`（含进位与全溢出回滚时间戳） |
| 4 | 许可证识别把标准 BSD 两条款文本判为 `NOASSERTION` | 许可证门禁误报 | 以「Neither the name」区分 BSD-3 / BSD-2；`gorilla/websocket` 正确识别为 BSD-2-Clause |
| 5 | 全局 `GOSUMDB=off` 与 `GOTOOLCHAIN=auto` 冲突，升 Go 版本后交叉构建报「checksum database disabled」 | 六平台构建中断 | Makefile 与 `gates.py` 项目级设 `GOSUMDB=sum.golang.org`（可覆盖），不改用户全局 Go 配置 |

## 7. ADR 变更清单（待评审批量决议）

`docs/adr/README.md` 中 0001–0020 **全部仍为 `Proposed`**。P0 代码已按这些 ADR 落地，但状态未转 `Accepted`，因此 `docs/README.md` 的状态机仍把整套文档视为「草案」。评审通过后的批量动作：

| 范围 | 现状 | 拟变更 | 生效条件 |
|---|---|---|---|
| ADR-0001 … ADR-0019（19 篇） | `Proposed` | `Accepted` | 架构师逐篇确认无冲突后批量转，并同步 `adr/README.md` 索引与状态分布 |
| ADR-0020（P0 实现基线与范围声明） | `Proposed` | `Accepted` | 评审确认三处规范修正、两处补定义、范围边界与 5 条已知限制 |
| `docs/README.md` §一 状态机 | 整套文档「草案」 | 按文档粒度标注「已批准」 | ADR 批量转 `Accepted` 之后 |
| `CHANGELOG.md` | `[0.1.0]` 未打 tag | 打 `v0.1.0` 附注标签 | `15` §3：标签附 changelog；仓库当前尚未初始化 git，需先完成 |

> **不得跳过**：按 `15` §4「决策的唯一真值源是 ADR」，在 ADR 仍是 `Proposed` 时启动 P1，等于让实现跑在未批准的决策上，正是 `14` §3 要防的返工（R-01）。

## 9. 评审后动作（P1 启动前置条件）

1. §1 签署表全部完成，结论记录进 `14` 的新增「评审结论」段与 `CHANGELOG.md`。

4. 初始化 git 仓库并打 `v0.1.0` 附注标签（`15` §3），把 `dist/` 证据留在 CI artifact 而非版本库。
5. 把 `make gates` 接入 CI（已在本轮加入），P1 首个 PR 前把覆盖率阈值改为 `--strict` 并消除 §5 的债务。
6. 完成上述 1–5 后，方可按 `14` §3 启动 P1（WBS 7–11）。
