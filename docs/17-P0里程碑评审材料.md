## 4. 本轮发现并修复的真实缺陷

| # | 缺陷 | 影响 | 处置 |
|---|---|---|---|
| 1 | `govulncheck` 报 `GO-2026-6809`：Go 1.27.2 标准库 `crypto/x509` 不再信任被入侵的中间 CA，调用链经 `store.WholeFileChecksum → io.Copy → x509.Certificate.Verify` 可达 | **安全**，影响 TLS 下载链路 | `go.mod` 与 CI 升到 Go 1.27.3；重跑 `govulncheck` 干净；见 `CHANGELOG.md` `Security` |
| 2 | `core.EventBus.Dropped()` 是文档化的诊断计数，但 `Publish` 从未累加 | 慢 WebSocket 客户端丢事件不可观测 | 改 `atomic.Int64` 累加（Publish 只持读锁，用 mutex 计数会数据竞争）；补 `TestEventBusDroppedCounterAndClose` |
| 3 | 覆盖率依赖 `TestULID` 的「同毫秒」时序，全量并行跑时在 89.4%–92.4% 之间抖动 | 门禁不可复现 | 补确定性 `TestIncrementEntropyCarry`（含进位与全溢出回滚时间戳） |
| 4 | 许可证识别把标准 BSD 两条款文本判为 `NOASSERTION` | 许可证门禁误报 | 以「Neither the name」区分 BSD-3 / BSD-2；`gorilla/websocket` 正确识别为 BSD-2-Clause |
| 5 | 全局 `GOSUMDB=off` 与 `GOTOOLCHAIN=auto` 冲突，升 Go 版本后交叉构建报「checksum database disabled」 | 六平台构建中断 | Makefile 与 `gates.py` 项目级设 `GOSUMDB=sum.golang.org`（可覆盖），不改用户全局 Go 配置 |
