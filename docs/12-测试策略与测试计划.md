## 1. 测试金字塔与分层

| 层 | 范围 | 工具 | 目标 | 运行时机 |
|---|---|---|---|---|
| L1 单元 | 纯函数、状态机、解析器、Remux 组件 | `go test`、fuzz | `core`/`security` ≥ 90%；`store`/`scheduler`/`transport/http`/`api`/`config`/`postproc`/`resolve`/`app` ≥ 80%；`cmd/*` 与 `internal/version` 只报告不设门禁（口径见 §8、`17` §3） | 每次提交 |
| L2 契约 | `Resource` JSON 往返、REST/WS/CLI schema、错误码 | `go test` + schema 校验 + 契约测试 | 接口零漂移 | 每次提交 |
| L3 集成 | Transport + Store + Scheduler 全链路（本地 fixture 服务器） | `httptest`、本地 FTP/SFTP、自建 tracker | 分片/续传/限速/重试正确 | 每次 PR |
| L4 **互操作** | 真实 BT 客户端、tracker、eMule 网络 | 容器化真实客户端 | 见 §3，全矩阵通过 | 每日 + 发布前 |
| L5 端到端 | UI/CLI → daemon → 落盘 → 后处理 | 自动化脚本 + 录制回放 | 关键用例 UC-01..UC-08 通过 | 每日 |
| L6 非功能 | 性能、故障注入、安全、兼容性 | 见 §4–§6 | 达到 NFR 指标 | 发布前 |

**原则**：站点解析测试一律用**录制回放 fixture**，禁止 CI 直连真实站点（规则会变、违反 ToS、结果不稳定）；真实站点只做人工冒烟。

## 3. 互操作回归套件（本项目最关键）

### 3.1 BT / Tracker 矩阵

| 编号 | 用例 | 通过标准 |
|---|---|---|
| BT-01 | 与 qBittorrent 双向：我方下载 / 对方做种 | 文件哈希一致 |
| BT-02 | 与 qBittorrent 双向：对方下载 / 我方做种 | 对方报告完成、`bytes_uploaded` 一致 |
| BT-03 | 与 Transmission / libtorrent 系客户端双向 | 同上 |
| BT-04 | 磁力：仅 DHT 获取元数据并完成下载 | 无 .torrent 文件也可用 |
| BT-05 | 自建 `chihaya` / `opentracker`：HTTP announce + scrape | 统计准确 |
| BT-06 | UDP tracker（IPv4 / IPv6 compact peer list） | peer 列表解析正确 |
| BT-07 | HTTPS tracker + passkey + 多 tracker 分层降级 | 主 tracker 挂掉后切备 |
| BT-08 | `private=1`：DHT / PEX / LSD 全部关闭 | 抓包验证无 DHT/PEX 流量 |
| BT-09 | 选择下载（多文件种子部分选中） | 未选文件不落盘 |
| BT-10 | WebSeed / uTP / MSE 连接 | 至少一条链路成功 |
| BT-11 | 做种策略：分享率与 `seed-time` 达标后停止 | 统计取统一 Task 模型 |
| BT-12 | 流式读取边下边播（`File.NewReader` 语义） | 首字节可读时间 < 阈值 |
| BT-13 | BT v2 **hybrid** 与 qBittorrent 互操作 | 已知支持不整齐，记录结果并默认 v1/hybrid |
| BT-14 | 诚实 PeerID 校验 | 抓包为 `-GT0001-` 或自定义但非伪装 |

> **P1 WBS 11 补记（2026-11-11）：上表仍是 L4 发布门禁，不是已通过项。**
> `internal/interop/suite.go:Registry()` 把 `BT-01..BT-14` 原序登记为**外部用例**
> （`ScopeExternal`），仅当提供隔离网络 + 真实 qBittorrent / Transmission / libtorrent +
> 自建 tracker 二进制 + 抓包设备，并通过 `--require-external --external-config` 执行
> 外部 harness 后才可能置为 `PASS`；`SKIPPED` / `UNSUPPORTED` **一律不计 PASS**。
> `BT-02`（我方做种）与 `BT-11`（分享率 / seed-time 策略）按 WBS 7 明确的产品边界标记
> `UNSUPPORTED`（`ScopeProductGap`），不是漏测。当前 `make interop` 实测
> **23 例：9 PASS / 0 FAIL / 12 SKIPPED / 2 UNSUPPORTED，L4 门禁 0/14，
> `release_gate_met: false`**，证据链 `dist/interop.json` → `dist/INTEROP.md`（CI 上传为 artifact）。
>
> 新增的 9 条 `L3-xx` 是**纯回环自动化补充证据**（`ScopeInProcess`，零新增依赖、零 cgo），
> 与 L4 不等价、不得相互替代：
>
> | 编号 | 用例 | 覆盖的 BEP / 门禁关联 |
> |---|---|---|
> | L3-01 | BEP 3 HTTP tracker：announce / scrape / compact v4+v6 / 503 与挂起故障注入 | BT-05 协议子集 |
> | L3-02 | BEP 15 UDP tracker：connect / announce / scrape / compact IPv4 | BT-06 协议子集 |
> | L3-03 | BEP 15 UDP tracker：IPv6 compact peer list（18B） | BT-06 协议子集 |
> | L3-04 | HTTPS tracker（自签证书）+ passkey + 主 tracker 故障后切备 | BT-07 协议子集 |
> | L3-05 | 真实 BT 线协议端到端：独立 seeder + 自建 tracker + `bttransport` | BT-01/03 线协议子集 |
> | L3-06 | BT 握手抓包：诚实 PeerID `-UD0000-`，非伪装 | BT-14 子集（仅回环，非真实客户端抓包） |
> | L3-07 | 纯磁力：仅 infohash 经 bootstrap peer 取 BEP 9 元数据并完成下载 | BT-04 子集（非 DHT） |
> | L3-08 | 多文件种子选择下载：未选文件字节不进入 `ChunkWriter` | BT-09 子集 |
> | L3-09 | 流式读取：4KiB 分片首片可读时延 | BT-12 子集（非「边下边播」验收阈值） |
>
> **门槛**：`make interop` 绿只说明上表本地部分健康；`make interop-gate` /
> `udinterop --release-gate-only` 在 14 条门禁未全绿时**明确失败**，且不接入 CI
> （CI 只跑 `make interop`，避免把未执行的外部矩阵伪装成通过）。NFR-PERF-01
> 千兆内网 1GiB ≥ 80MB/s 基准（`12` §5）同样**未执行**。

##### L4 门禁可满足性冲突（2026-11-13 登记，待评审处置）

**这不是环境缺失，而是验收判据与已批准产品边界的冲突。** 按 ADR-0004 与
`14` §11 序 4 交付边界，`internal/transport/bt` 固定 `NoUpload=true` / `Seed=false`，
不提供上传槽、分享率与 `seed-time` 策略。因此：

| 用例 | 判据 | 当前边界下的结论 |
|---|---|---|
| `BT-02` | 与 qBittorrent 双向：对方下载 / 我方做种 | `UNSUPPORTED`（产品明确不做，非漏测） |
| `BT-11` | 做种策略：分享率与 `seed-time` 达标后停止 | `UNSUPPORTED`（同上） |
| `BT-03` | 与 Transmission / libtorrent 系客户端双向 | 半向可达（对方做种 → 我方下载），「我方做种 → 对方下载」不可达 |
| `BT-01` / `BT-05..10` / `BT-12..14` | 单向下行 / tracker / 抓包 / 流式 | 需隔离实验室，条件齐备后可达 |

于是 `14` §11 的收口条件「**14/14 PASS 且基准达标**」在现有产品边界下
**形式不可满足**：即使补齐真实命名客户端、`chihaya` / `opentracker` 二进制、抓包设备
与千兆内网，`BT-02` / `BT-11` 也不可能置为 `PASS`。本轮新增的 `BX-03` / `BX-04`
（真实 libtorrent 单向证据）同样不解除该冲突。

**处置路径（须由评审组按 `15` 的变更管理流程与 `docs/README` §一状态机决定；
本轮不擅自改判据或已批准 ADR）**：

1. **修订判据（保持产品边界，推荐）**：把 `BT-02` / `BT-11` 与 `BT-03` 的我方做种半向
   标为「产品非目标豁免」，门禁改为「适用用例全 PASS + 非目标用例显式豁免并经评审签署」，
   同步 `16` §7 文案与 ADR-0004 实现落地段；
2. **扩大产品范围**：实现受限做种 / 上传与分享率策略，须修订 ADR-0004、重评 R-10
   吸血风险与 PT 礼仪，属于新功能范围而非测试工作；
3. **保持开放**：不修订，则 `release_gate_met` 恒 `false`、序 6 永不关闭，且须在
   `14` §11 明确「阻塞源自判据冲突，而非仅环境缺失」。

**在评审签署前**：`BT-02` / `BT-11` 继续 `UNSUPPORTED`，其余 L4 继续 `SKIPPED`；
`make interop-gate` 继续明确失败；`UNSUPPORTED` **不得**改写为 `PASS`，也**不得**
以「豁免」名义计入通过数。任何豁免必须附带可追溯的评审签署证据。

#### 3.1.2 阻塞根因二次校准（2026-11-13，ADR-0021 提案待评审）

**§3.1「L4 门禁可满足性冲突」与 §3.1.1 中的「ADR-0004 不做种边界」

| 已批准依据 | 要求 |
|---|---|
| ADR-0004「后果 / 负面」 | 「默认 `Seed=false`，**做种策略须自行实现**」 |

> **① 实现相对已批准 ADR 与 M 级需求的未签署范围缩减（合规差距，根因）；
> ② 该缩减与「14/14 PASS」判据的形式冲突；③ 真实实验室条件缺失。三者并存。**

#### 3.1.4 L4 证据包完整性审计（不是执行证据）

> **性质**：`make l4-audit` 只回答「这份 `ud.interop/v1` 证据包的汇总、
> 门禁覆盖与 `release_gate_met` 是否与它自己的 case 列表自洽」。
> 它**不执行**任何 `BT-*` 用例、不启动外部进程、不访问网络、不写回被审计文档，
> **不是** L4 执行证据，也不替代 `make interop-gate` 的发布门禁判定。

| 检查 ID | 重算内容 |
|---|---|
| `AUD-SCHEMA` | `schema` 必须为 `ud.interop/v1` |
| `AUD-GATE-COVERAGE` | 门禁用例恰为 `BT-01..BT-14` 共 14 条，无缺 / 多 / 重；非规范用例不得标 `gate` |
| `AUD-STATUS-ENUM` | 每条 status 仅允许 `PASS` / `FAIL` / `SKIPPED` / `UNSUPPORTED`，且 ID / reason 非空 |
| `AUD-SUMMARY` | `total` / `gate_total` / `gate_pass` / `pass` / `fail` / `skipped` / `unsupported` 全部按 case 重算比对 |
| `AUD-GATE-VERDICT` | `release_gate_met` 必须等于「0 FAIL 且 14/14 gate PASS」的重算结果 |
| `AUD-GATE-REASON` | 原因串不得在未全 PASS 时写「全部 PASS」 |
| `AUD-EXTERNAL-FLAG` | 声称门禁达标必须 `require_external=true`（本地回环报告不得冒称达标） |
| `AUD-PASS-EVIDENCE` | 每条 PASS 门禁用例须带 `reason` 与 `evidence`（§3.1.3 / `18` §7.3 留痕要求） |
| `AUD-SUPPLEMENTAL` | `BX-*` 补充证据 status 合法，且**永不**翻转门禁计数 |

非法 JSON 报 `AUD-PARSE`，文件不可读报 `AUD-INPUT` / `MISSING`；任一检查失败即
`INCONSISTENT` 并列出失败项。`--require-gate-met`（`L4_AUDIT_FLAGS`）可追加
「重算门禁必须为真」的判定，但**权威门禁仍是 `make interop-gate`**。

本机实测（2026-11-14）：示例 stub 产物审计 `CONSISTENT`、9/9 检查 OK、
重算 `gate_pass=0/14` / `release_gate_met=false`；把 `release_gate_met` 手工改
`true` 且 `summary.pass` 改 99 的副本审计 `INCONSISTENT`，精确报出
`AUD-SUMMARY` 与 `AUD-GATE-VERDICT`；缺文件报 `MISSING`。
三者都**没有**改变 `dist/interop.json:release_gate_met`，也**没有**新增任何 L4 证据。
回归用例见 §9 `TestAudit*`（11 项）。

## 4. 故障注入

| 场景 | 期望 |
|---|---|
| 进程 `kill -9` 后重启 | 已落盘分片 100% 复用，无重复下载、无损坏 |
| 分片被外部篡改 | 校验失败 → 只重下该片 |
| 镜像全部失败 / 部分失败 | 切换镜像；达上限才判失败 |
| tracker 超时 / DNS 失败 / 5xx | 指数退避 + 降级，不阻塞其他任务 |
| 磁盘写满 / 只读目录 | `E_STORAGE_FULL`，任务暂停且可恢复 |
| sidecar 崩溃、无响应、版本过低 | 自动重启 3 次；最终 `degraded`；其余下载不受影响 |
| ffmpeg 执行中用户取消 | 进程组/进程树被杀，无残留写文件 |
| 恶意 Metalink（私网 URL、超大 XML、镜像 1000 个） | SSRF/上限拦截，无 OOM |
| 恶意 m3u8（路径穿越、`file://`、超多分片） | 拦截并告警 |
| 插件死循环 / 抛异常 | 超时强杀，任务转 `E_RESOLVE_FAILED` |
