## 1. 扩展点总览

| 扩展点 | 用途 | 默认运行时 | 是否可热更新 |
|---|---|---|---|
| `Resolver` | 新增链接封装 / 站点解析 | 进程内 Go / goja 插件 | ✅ 规则包 |
| `Transport` | 新增传输协议 | 进程内 Go（不建议插件化） | ❌ 需发版 |
| `PostProcessor` | 新增后处理（Remux 变体、Transcode） | 进程内 Go / sidecar 适配 | 部分 |
| `SourceRule` | 站点规则（选择器、签名、格式提取） | goja（ES5.1）/ 可选 WASM | ✅ 独立通道 |
| `CredentialProvider` | 凭据获取方式 | Go | ❌ |

> 原则：**Resolver 处理不可信输入，插件必须默认无网络、无文件、无环境变量能力**，能力按 manifest 显式授予。

## 2. 插件 manifest

```json
{
  "name": "site.example",
  "version": "1.2.0",
  "apiVersion": "ud.plugin/v1",
  "type": "resolver",
  "runtime": "goja",
  "entry": "index.js",
  "match": ["^https?://([^/]+\\.)?example\\.com/video/"],
  "capabilities": {
    "http": { "allowedHosts": ["example.com", "*.cdn.example.com"], "maxRedirects": 3 },
    "fs": false,
    "env": false,
    "subprocess": false,
    "crypto": ["sha256", "base64"]
  },
  "limits": { "timeoutMs": 10000, "memoryMB": 32, "maxResponseBytes": 1048576 },
  "signature": "ed25519:BASE64...",
  "author": "...", "license": "MIT"
}
```

| 字段 | 约束 |
|---|---|
| `runtime` | `goja`（起步）或 `wasm`（wazero/Extism，硬隔离） |
| `capabilities.http.allowedHosts` | 必填白名单；空数组 = 完全无网络 |
| `subprocess` / `fs` / `env` | Resolver 插件默认 `false`，开启需安全评审 |
| `limits` | 强制超时、内存与响应大小上限 |
| `signature` | 官方仓库插件必须 Ed25519 校验；本地开发可 `--insecure-plugins` |

## 3. goja 插件契约

```javascript
// index.js —— 声明式站点规则
export const meta = {
  name: "site.example",
  version: "1.2.0",
  match: [/^https?:\/\/([^/]+\.)?example\.com\/video\//]
};

// ctx 由宿主注入，只有白名单内的能力
// ctx.http.get(url, {headers}) -> {status, body, headers}
// ctx.log.info(msg) / ctx.base64.decode(s) / ctx.sha256(bytes)
export function resolve(url, ctx) {
  const html = ctx.http.get(url, { headers: { "User-Agent": "UD/1.0" } }).body;
  const m = /"playUrl":"([^"]+)"/.exec(html);
  if (!m) throw new Error("RULE_OUTDATED: playUrl not found");
  return {
    files: [{ index: 0, path: "video.mp4" }],
    mirrors: [{ url: unescape(m[1]), priority: 1 }],
    headers: { "Referer": url },
    identity: { isAdaptive: false }
  };
}
```

**宿主义务**：① 用 `ResolveContext.Guard` 校验所有产出 URL；② 注入的 `ctx.http` 只能走白名单且逐跳校验重定向；③ 捕获 panic 并转为 `E_RESOLVE_FAILED`；④ 规则抛 `RULE_OUTDATED` 时上报并尝试兜底 Resolver（yt-dlp）。

> goja 仅支持 **ES5.1**：不得使用 `async/await`、可选链、`fetch`、ES Module 语法（宿主做转译包装）。需要现代 JS 或强隔离时改走 WASM。

## 4. WASM 硬隔离（可选进阶）

| 方案 | 特点 |
|---|---|
| `wazero`（纯 Go，零 cgo） | 进程内 WASM 运行时，可精确裁剪 WASI 的 `net`/`fs`/`env` 能力，保持单二进制 |
| `Extism` | 插件 SDK 成熟、跨语言（Rust/Go/JS→WASM），便于生态分发 |
| `wazero + QuickJS-WASM` | 可在进程内跑现代 JS 挑战脚本，但工程量大；YouTube 对抗逻辑仍不建议自行维护（ADR-0010） |

选择判据：**规则来源可信度低 / 需要第三方贡献 → WASM**；仅团队自维护的中文站规则 → goja 足够。

## 5. 内置实现的安全优先级

`thunder://` 解码、Metalink 解析、SSRF Guard、凭据脱敏等安全敏感 Resolver **必须内置且不可被插件覆盖**。插件 `Match()` 优先级恒低于内置实现，注册时若 `match` 与内置冲突直接拒绝加载。

**实现落地（2026-11-10，WBS 7/8/9/10 后当前态）**：`internal/app/daemon.go:newBuiltinResolvers()` 的注册顺序固定为
`metalink → link-wrapper → magnet → torrent → [plugin] → direct-http → direct-file → unsupported`，
`Unsupported` 恒为最后一个；`plugins.dir` 未配置时 `[plugin]` 不存在，链退化为 7 个内置 Resolver。
`internal/app/daemon_test.go::TestBuiltinResolverChainOrderAndDispatch` 与 `::TestPluginResolverPlacementInChain` 断言该顺序。

**「插件优先级恒低于内置」的精确含义**：ADR-0014 §4 点名不可被覆盖的是 thunder 解码、Metalink、SSRF Guard 等**安全敏感/协议专属**实现，它们全部排在插件之前；`direct-http` 是匹配一切 http(s) URL 的**通用兜底**，若排在插件之前，站点规则将永无机会命中，故插件位于其之前。此外 `internal/plugin/manifest.go:Validate()` 会在加载期直接拒绝命中
`thunder://` / `flashget://` / `qqdl://` / `magnet:` / `ed2k://` / `file:` / 裸 bencode 种子等哨兵的 `match` 规则，即使注册顺序被误改也无法遮蔽内置实现。

`InputMetalink` / `InputThunder` / `InputMagnet` / `InputTorrent` 若落到 `Unsupported`，返回「注册链断裂」的 `E_RESOLVE_FAILED` 而不是「尚未实现」。

## 6. 示例：`thunder://` 解码 Resolver（内置，约 20 行）

```
输入 thunder://BASE64
→ base64 解码 → 校验前缀 "AA" 与后缀 "ZZ" → 取出中间原始 URL
→ 校验 scheme ∈ {http, https, ftp, ed2k} → 构造单文件 Resource
→ 交回自有 HTTP/FTP Transport
```

`flashget://`（首尾加 `[FLASHGET]`）、`qqdl://`（Base64 变体）同理。**迅雷 P2SP / 高速通道 / 离线下载为私有协议，无开源实现，本项目只做解码**（ADR-0007）。

实际实现见 `internal/resolve/wrapper.go`：容忍缺 padding / URL-safe 字母表 / 尾斜杠，
但拒绝空载荷、控制字符、超限长度与非白名单 scheme；解码后的 URL 再过一次 SSRF Guard，
拒绝内嵌凭据。文件名统一走 `internal/resolve/filename.go` 的路径穿越清理。

## 7. Metalink Resolver（内置，纯 Go）

- RFC 5854 XML：解析 `<file>`（name、size）、`<url>`（priority、location、type）、`<hash>`、`<pieces>`（type、length）、`<metaurl>`；兼容 v3 旧命名空间。
- RFC 6249 HTTP 头：`Link: <...>; rel=duplicate; pri=; geo=`、`Digest: SHA-256=`。
- 纯 Go 实现（约 300–500 行）；可复用 `dpb587/metalink`（MIT）的 v4 结构体，**禁用 `libmetalink`（C 库，引入 cgo）**。
- 视为不可信输入：XML 大小上限（默认 4MiB）、镜像数量上限（默认 32）、禁止 DTD/外部实体、逐 URL 过 SSRF Guard、整文件与分块哈希必须校验。

**实现落地（2026-11-10）**：`internal/resolve/metalink{,_xml,_http}.go`。解析器忽略命名空间前缀以兼容 v3/v4 混写；`<metaurl>` 不作镜像；`Digest` / `Content-Digest` 按算法强度择优（md5 < sha-1 < sha-256 < sha-512）并转成小写 hex。清单字节只能来自本地 `.meta4/.metalink`、内联 XML 或 `ResolveContext.Options`，**Resolver 不发起任何网络请求**。冻结的 `Resource` 只有全局 `Mirrors` / `Checksum`（ADR-0013），因此多 `<file>` 清单显式拒绝而非错配镜像；`<pieces length>` 会锁定 `Limits.ChunkSize`，`internal/store/checksum.go` 按声明算法逐片校验，失败只重下该片。

## 8. 开发、调试与发布流程

1. `udctl plugin scaffold <dir>` 生成 manifest + 样例 `index.js` + `cases.json` 回放夹具（已实现，拒绝覆盖已有文件）。
2. `udctl plugin keygen` / `udctl plugin sign <dir> --key <priv>` 离线生成与写入 Ed25519 签名（已实现）。
3. `udctl plugin verify <dir> --key <pub>` 做 manifest 校验、签名校验、静态禁用 API 扫描与 goja 编译（已实现；本地开发可 `--insecure-plugins`）。
4. `go test ./internal/plugin/...` + `udctl plugin test <dir> --fixture cases.json` 跑录制回放用例（已实现；**回放 Doer 从不发起真实网络请求**，未录制的 URL 返回 404 使遗漏显式失败）。
5. `udctl plugin list <dir>` 查看本地规则目录的 active / rejected 状态（已实现）。
6. 提交到规则仓库 → CI 跑沙箱用例 + 许可证扫描 → 签名发布（**流程约定，规则仓库与发布流水线尚未建立**）。
7. 客户端从 `plugins.dir` 独立规则通道按 `reloadInterval`（默认 30s）轮询，校验签名后原子热加载；**规则包更新与主程序发版解耦**（已实现；见 §10）。
8. 规则失效遥测（默认关闭、需用户同意）只上报 `plugin name + version + error code`，不上报 URL 与凭据（**尚未实现**，当前只在 daemon 日志中记录，且不含 URL）。

## 9. 评审清单（PR 必查）

- [ ] manifest `capabilities` 最小授权，无 `subprocess` / `fs` / `env`
- [ ] 所有 URL 经 `ctx.http` 白名单与 SSRF Guard
- [ ] 有超时、内存、响应大小限制；有 `RULE_OUTDATED` 明确错误
- [ ] 不读取、不打印、不回传凭据
- [ ] 产出 `Resource` 符合 `05` §3 / `06` §4 schema
- [ ] 不自行写文件、不自行下载（Resolver 只描述）
- [ ] 许可证兼容、签名有效、有回放测试用例

## 10. 实现落地（P1 WBS 10，2026-11-10）

| 关注点 | 实现位置 | 说明 |
|---|---|---|
| manifest 与严格校验 | `internal/plugin/manifest.go` | `apiVersion=ud.plugin/v1`、`type=resolver`、`runtime=goja`；`entry` 限定包内 `.js`（拒绝 `..` / 绝对路径 / 符号链接逃逸 / 512 KiB 上限）；`match` 逐条编译并拒绝与内置冲突；`fs`/`env`/`subprocess` 为真直接拒绝加载；`allowedHosts` 支持精确与单层 `*.` 通配，拒绝裸 `*`；`limits` 缺省 10s / 32MB / 1MiB，硬上限 60s / 256MB / 8MiB |
| ES5.1 静态扫描与转译 | `internal/plugin/scan.go` | 宿主把 `export const|var|function` 改写为 `var` / `function` 并包进严格模式 IIFE；扫描前先抹除注释、字符串与正则字面量，拒绝 `async/await`、`import`、`require`、`fetch`、`eval`、`Function()`、`__proto__`/`constructor`、`process`/`Deno`/`globalThis`、箭头函数、可选链、模板字面量、展开、`for..of`、`const/let/class` 等 |
| 签名 | `internal/plugin/signature.go` | `payload = SHA256(canonicalManifestJSON ‖ 0x00 ‖ entryScriptBytes)`，签名写作 `"ed25519:" + base64(Ed25519.Sign(priv, payload))`；**脚本任一字节变化即失效**；无签名 / 无受信公钥 / 公钥不匹配一律 fail-closed，仅 `plugins.insecure`（或 `udd --insecure-plugins`）可跳过且限回环监听 |
| 运行时与能力裁剪 | `internal/plugin/runtime.go`、`http.go` | 每次 `Resolve` 新建 goja VM；只注入 `ctx.http.get`（逐跳白名单 + SSRF Guard + 手动重定向 + `maxResponseBytes`）、`ctx.log`、`ctx.base64`、`ctx.sha256`；`fs`/`env`/`subprocess`/`require` 从不存在；敏感请求头（`Authorization`/`Cookie`/`Host`/`X-Api-Key`）禁止设置 |
| 时限与内存 | `internal/plugin/runtime.go` | `vm.Interrupt` 看门狗按 `timeoutMs` 强杀死循环并转 `E_RESOLVE_FAILED`；`memoryMB` 约束所有宿主可见分配（响应体、输出 JSON）与调用栈深度。**goja 无 per-VM 堆上限**，真正的硬隔离仍属 WASM 升级路径（ADR-0014 §5），不得对外宣称「内存硬隔离」 |
| 产出校验 | `internal/plugin/resource.go` | 只接受白名单字段的 JSON；每个镜像 URL 过 `allowedHosts` + `security.SSRFGuard`，每个输出路径过 `security.PathGuard`，剔除凭据头、拒绝负长度与未知摘要算法；`Resource` 字段按 ADR-0013 冻结结构构造，插件不能指定 engine / 凭据 / 状态 |
| 热更新 | `internal/plugin/manager.go` | 目录内容指纹（manifest + `.js` 内容哈希）变化即原子换快照；单个包校验/签名/编译失败时**保留上一份可用版本**并登记 `Failures()`；`Watch(ctx)` 纯标准库轮询，不发版、不重启 daemon |
| 规则失效 | `internal/plugin/runtime.go`、`manager.go` | JS 抛 `RULE_OUTDATED` → `E_CAPABILITY_UNAVAILABLE` + `Details["reason"]="RULE_OUTDATED"`；`Manager` 调用内置 `direct-http` 兜底 Resolver，兜底失败仍返回原分类错误，**不静默丢弃任务**。yt-dlp 兜底属 P2+，当前未实现 |
| 注册 | `internal/app/daemon.go` | `plugins.dir` 为空时链中完全没有插件 Resolver；配置后置于协议专属内置之后、通用 `direct-http` 之前（见 §5） |

**明确边界（不得对外宣称已具备）**：WASM / Extism 硬隔离、第三方规则仓库与发布流水线、规则失效遥测、`lux` 站点解析、`yt-dlp` 兜底、插件 REST 管理端点、真实站点 L4 互操作矩阵。当前自动化证据为离线录制回放与本地回环，未连接任何真实站点。
