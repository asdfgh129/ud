# 10 技术选型与依赖清单

> 文档编号：UD-DOC-10 ｜ 版本：v0.3 ｜ 状态：草案（P0 依赖已 pin，供应链门禁已执行） ｜ 日期：2026-11-09 ｜ 复核周期：每季度

> **v0.2 说明**：§3 是**全里程碑目标依赖表**，绝大部分尚未引入。P0 实际 pin 的直接依赖只有 3 个，见 §7；请勿把 §3 当作当前 `go.mod` 内容。`tools/check_arch.py` 守卫 5 禁止 `mattn/go-sqlite3`、`aria2`、`libtorrent` 进入模块图。

## 1. 选型原则

1. **纯 Go 优先**：能用 Go 库就不用 cgo；能用进程内就不用子进程。
2. **许可证分级**：核心链路只用 MIT / MPL / ISC / Apache / BSD；GPL 一律隔离或不用；LGPL 仅以 exec 形态 arm's-length 使用。
3. **成熟度优先于新特性**：优先有生产用例、持续维护的库；v0.x 新库必须配套互操作回归。
4. **可替换性**：所有外部库通过 `05` 的接口接入，禁止在 `core` 中 import 具体实现。
5. **移动端可达**：任何依赖都不得要求派生子进程或 cgo。

## 2. 语言与框架决策

| 方案 | 结论 | 理由 |
|---|---|---|
| **Go（核心）** | ✅ 采用 | 单二进制静态编译、全平台含移动端；协议库最齐（`anacrolix/torrent` + `goed2k` + `net/http` + `goja` + `goproxy` 全在进程内）；goroutine 天然适合分块并发；Gopeed 已验证路线 |
| Rust | ❌ 备选 | `librqbit` + `reqwest` 性能好，但 ed2k / 站点解析库缺失，sidecar 更多 |
| C++ / Qt | ❌ 仅可选 BT 后端 | libtorrent 2.0 最强，但 Boost 依赖、打包重、迭代慢 |
| Python | ❌ 仅 sidecar | yt-dlp 原生，但打包/GIL/常驻守护进程不合适 |
| Electron / TS | ❌ 仅 UI 备选 | 体积大，不适合下载内核 |

UI：Flutter（一套覆盖 6 端，Gopeed 验证）或 Tauri（更轻）；核心必须做成 daemon + REST/WS，UI 可替换。

## 4. 许可证矩阵与合规动作

| 许可证 | 涉及组件 | 风险 | 必须动作 |
|---|---|---|---|
| MIT / ISC / BSD / Unlicense | goed2k、lux、gotd、goja、mp4ff、mkvgo、jlaffaye/ftp、yt-dlp、N_m3u8DL-RE | 低 | 保留版权声明与 LICENSE 文件 |
| **MPL-2.0** | `anacrolix/torrent`、`metainfo` | 低-中 | 修改过的 MPL 文件需以 MPL 提供；静态链接商业版相对友好；记录修改清单 |
| **LGPL-2.1+** | ffmpeg（**必须锁定 LGPL 构建**） | 中 | 不带 `--enable-gpl` / `--enable-nonfree`；**exec 独立 CLI 不触发链接，是最干净形态**；随附与二进制精确对应的源码 + configure 行；About/EULA 声明；EULA 不得禁止逆向；保留 `buildconf` |
| **GPL-2.0** | ~~aria2c~~、~~aMule/amuled~~ | 高 | **已全部从依赖中移除**（ADR-0003）；如未来接入 BYO 适配器，保持独立进程 arm's-length 并请法务确认 |

## 5. 已否决方案（避免反复讨论）

| 方案 | 否决理由 | ADR |
|---|---|---|
| `aria2c` 承担任何传输（含仅 BT） | 双调度器；RPC 黑盒；GPL；移动端无法起子进程 | ADR-0002 / 0003 |
| `libmetalink` | C 库需 cgo，破坏单二进制与移动端 | ADR-0006 |
| `Telethon` / Python 承载 Telegram | `gotd/td` 纯 Go 已足够，零新增进程 | ADR-0009 |
| `TDLib` cgo 进程内 | 原生依赖与 ABI 负担，破坏交叉编译 | ADR-0009 |
| ffmpeg 以 cgo 静态链入 | 破坏交叉编译 + LGPL §6 合规更难 | ADR-0011 |
| `ffmpeg.wasm` | 内存/性能/无硬加速，下载器场景不可用 | ADR-0011 |
| 捆绑 aria2 做 RPC 兼容层（L2） | 保留协议规范即可，程序完全不需要 | ADR-0019 |
| 用 goja 硬扛 YouTube JS 挑战 | ES5.1 常跑不动现代脚本；站点对抗逻辑需长期团队维护 | ADR-0010 |
| 整体引入 `go-aria2` / `goaria` | 自带下载引擎，等于请回第二个调度器；只可复用方法清单与结构体 | ADR-0003 |

**观察项（不采纳）**：`aria2-next` v3.0.9（2026-10）换用 libtorrent-rasterbar 2.1，补 BT v2/uTP/ED2K/HLS/DASH，RPC 兼容；但 ~700 star、仍 GPL-2.0、不导入旧 `.aria2` 状态，不宜作为架构基石。

## 6. 版本策略

- `go.mod` 精确 pin；Renovate/Dependabot 每周提 PR，安全补丁走加急通道。
- `anacrolix/torrent`、`goed2k` 升级必须跑 `12` 的互操作回归套件后才合入。
- **yt-dlp / 站点规则走独立更新通道**，与主程序发版解耦；规则失效属常态而非事故。
- ffmpeg 按 major 版本分支命令模板；每个平台槽位记录 `version + buildconf + sha256`。
- 每次发布生成 SBOM（CycloneDX），跑 `govulncheck` 与许可证扫描作为发布门禁（`13`）。
